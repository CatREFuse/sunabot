# Web Chat 截止与取消

## 用户目标

管理员在 Web Chat 发送消息后，可以在十分钟内得到回复或明确失败；关闭页面连接、取消请求或停止服务时，正在等待的回合会及时结束，后续消息不会被永久堵塞。

## 角色与环境

- 角色：已认证管理员。
- 环境：隔离 Workspace；使用受控 Runtime，分别模拟正常回复、忽略取消且永不返回、迟到返回。
- 会话：当前 Agent 的 `web:admin`。

## 输入

1. 发送一条正常消息并等待回复。
2. 发送一条 Runtime 永不返回的消息，将时钟推进至 599,999 毫秒和 600,000 毫秒。
3. 在消息执行中断开 HTTP 客户端。
4. 在消息执行中关闭应用。
5. 在超时或取消后发送下一条消息。

## 预期结果

- 正常消息只产生一条浏览器回复，不经 OneBot 外发。
- 599,999 毫秒时请求仍在等待，600,000 毫秒时返回 `WEB_CHAT_REPLY_TIMEOUT`，即使 Runtime 忽略取消也会结束 HTTP Promise 并释放顺序队列。
- 客户端断开会取消当前信号；关闭应用会在等待请求排空前取消全部 Web Chat 回合。
- 已取消的排队消息轮到执行时不会记录入站消息、调用模型或生成回复。
- 迟到的 Runtime 结果不能写入 Web delivery，也不能覆盖超时或关闭结果。
- 下一条合法消息可以继续执行。

## 质量标准

- 超时、断开和关闭拥有稳定状态，不显示内部路径、堆栈或 Provider 内容。
- 同一 Agent 的正常消息仍保持严格顺序，不重复回复。
