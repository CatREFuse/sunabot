# QQ 账号自动转移

## 用户目标

已认证管理员在当前 Agent 的新 NapCat 账号中登录一个已归属其他 Agent 的 QQ 时，系统自动释放旧账号并完成归属转移，无需手工查找和解绑旧记录。

## 角色与环境

- 角色：已认证管理员。
- 环境：隔离 Workspace；两个已启用 Agent 各有一个独立 NapCat 账号。
- 账号：旧账号已登记目标 QQ，新账号完成同一 QQ 的扫码登录。

## 输入

1. 在新 Agent 的账号登录窗口扫描已归属旧 Agent 的 QQ。
2. 分别覆盖旧账号 OneBot 在线、旧账号确认离线、旧账号状态不可确认三种状态。
3. 旧账号收到 `KICKEDOFFLINE` 下线通知，NapCat 仍保留旧的已登录快照。
4. 在转移期间并发刷新新账号登录状态，并在完成后模拟旧账号迟到断线和 Core 重启。

## 预期结果

- 旧账号 OneBot 在线时，系统先关闭旧账号的快速登录并发送退出动作，强制重启该账号的 NapCat 容器，再以单个 SQLite 事务把 QQ 归属切换到新账号。
- 旧账号确认离线时，系统关闭其快速登录并重启该账号的 NapCat 容器，再完成归属切换。
- `KICKEDOFFLINE` 不再显示为“已登录”；登录弹窗自动进入“正在恢复登录”，只重启当前账号容器，并在恢复后显示新的二维码。
- 转移成功后旧账号不再保存该 QQ，新账号保存该 QQ；重复状态刷新保持幂等，不重复退出或反向转移。
- 旧账号状态无法确认、容器重启失败或持久化失败时不写入部分归属，登录窗口显示明确失败，数据库继续只有一个 QQ 归属。
- Core 重启后新归属保持稳定，旧账号不会通过历史快速登录重新抢回绑定。

## 质量标准

- 管理员完成新账号扫码后无需进入旧 Agent 操作。
- 成功状态只显示当前账号已在线；恢复中的旧账号只显示状态和结果，不展示 QQ 的原始 `KICKEDOFFLINE` 安全告警、内部路径、数据库语句、NapCat Token 或堆栈。
- 会话、记忆、队列和历史数据仍保留在各自 Agent，不随 QQ 账号归属转移。
