# QQ 登录二维码时效

## 用户目标与环境

管理员管理台，Linux/WSL Native Core 与每账号独立 NapCat。打开 QQ 登录弹窗获取新二维码，过期后遮罩并由管理员点击刷新。保留现有账号与登录缓存。

## 输入与验证

使用合成二维码、受控登录接口与浏览器时钟，无模型、QQ 外发或真实聊天数据。打开未登录账号时，状态接口中的旧图片不得展示，必须等待刷新返回新的图片。已登录及暂时离线但仍有登录态的账号保持现有连接恢复流程。

刷新接口必须确认图片内容更新；仅接受请求、文件触碰、超时、损坏图片均不得返回旧图作为刷新成功。图片从生成时间起最多展示 60 秒，这是保守展示窗口，不代表腾讯保证的有效期。服务端超过窗口不返回图片，客户端显示剩余秒数，到期移除图片并遮罩，必须点击刷新；后台休眠恢复后重新计算时效。上游提前报错、状态读取失败、手动刷新开始时也隐藏图片。轮询不得解除过期或失败遮罩，不得被刷新前的迟到响应覆盖。

## 预期输出与质量标准

桌面与移动端 light/dark 均可见倒计时、过期状态和刷新按钮；遮罩下不存在可扫码图片。关闭重开必须重新刷新，切换账号后旧响应不污染新弹窗，登录完成仍可正常显示在线。后端测试、Vue 计时与并发测试、浏览器交互与截图共同验证，不通过模型夹具替代这些确定性检查。真实 NapCat 重启后单独核对新二维码、Core 与其他账号未重启；收信需要手机登录确认。
