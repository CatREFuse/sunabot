# QQ 连接状态与断连恢复

## 用户目标与环境

管理员群聊，Windows 11 上的 WSL Native Core 与每账号独立 NapCat。管理员查看当前 QQ 的实际在线状态、最近消息与事件，在短暂断连恢复期间保留已有登录缓存。

## 输入与验证

隔离管理 API 与真实 Vue composable 分别模拟耗时 15 秒的状态查询、缓存身份仍存在但 `online=false`、两个 QQ 仅一个继续发送心跳、单账号 WebSocket 断开与重连。向生产 OneBot ingress 输入不同账号的事件，确认事件时间互不覆盖。页面切换 QQ、状态读取失败与恢复均检查显示。

## 预期工具与输出

无需外部 Provider 或 QQ 外发。状态轮询等待当前请求完成，不在第 10 秒取消；未知状态不显示离线或沿用已在线结果。QQ 在线依据 NapCat 的 `online` 与 OneBot `get_status`，不凭账号 ID 或登录缓存推断。临时离线保留登录缓存并等待 NapCat 自身恢复，不自动调用 `bot_exit` 或建立手动登录标记；管理员仍可确认退出并重新登录。等待恢复期间若变为登录失效，界面提供明确的重新登录操作，不因定时查询自动退出。后台扫码完成监测持续到实际在线且登录已持久化，关闭弹窗不影响完成；每个账号分别提供最近事件、最近消息和断连通知。

## 质量标准与验收边界

单元测试覆盖慢请求、取消与账号切换、实际离线及恢复、账号事件隔离；light/dark 界面截图核对在线、断开、未知与恢复中状态。生产验收由管理员环境检查实际入站消息、NapCat 升级后的连接重建和所选 QQ 状态一致性。隔离测试不证明腾讯账号会话失效已根治，也不以模拟消息代替真实 QQ 收信。
