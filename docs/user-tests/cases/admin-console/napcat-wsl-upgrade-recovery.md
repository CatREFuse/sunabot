# NapCat 升级与 WSL 对时恢复

## 用户目标

管理员升级现有 NapCat 并修复 WSL 对时引起的运行状态误判，保留全部 Agent 数据、账号配置和 QQ 登录态，升级后能够接收真实消息并正确显示连接状态。

## 角色与环境

- 主对话角色：管理员群聊；操作入口：已认证管理员管理台与宿主启动器。
- 环境：Windows 11、Ubuntu 24.04 WSL2、Native Core、每账号独立 NapCat Docker。
- 当前账号：已有登录态的 QQ；其他账号保留各自原有状态。
- 此用例是部署与真实 QQ 验收，不调用外部模型夹具，不发送合成消息到真实群聊。

## 输入与操作

1. 记录当前组件版本、各账号登录状态、容器挂载、进程身份和最后真实入站时间。
2. 核验 NapCat 4.18.30 的 OCI 多架构清单与镜像摘要，拉取固定摘要镜像。
3. 使用 `./sunabot.sh down` 停止当前部署。以显式 workspace 创建并校验全部 Agent 的离线业务库与队列库恢复点，同时归档 QQ 登录目录、账号配置与部署文件。
4. 应用稳定进程身份、状态查询与轮询修复，升级组件锁。修复 Windows 时间源后，消除 WSL 的重复对时控制。
5. 使用 `./sunabot.sh up` 启动当前部署，观察账号自行恢复登录、OneBot 连接和真实消息入站。
6. 在保留 QQ 登录进程的条件下，短暂断开已验证属于目标账号的 OneBot 连接，观察自动重连及后续真实入站。
   - 覆盖客户端已断开、Core 仍保留旧 TCP 连接的半开情况；旧连接不再回应 WebSocket ping 时，正常事件循环下 10—20 秒回收，随后同账号可重新接入，健康的其他账号保持在线；主机休眠或事件循环停顿不计入此上限。
   - 旧连接仍回应 pong 时，重复连接继续返回 409；关闭 Gateway 后不遗留探活定时器。
7. 对比启动器、管理 API 与管理台状态；检查桌面和移动端的浅色、深色截图。

## 预期结果

- 全部业务库和队列库通过 SQLite integrity、外键与备份记录数校验；升级不清空记忆、会话、账号或 QQ 缓存。
- 镜像版本为 4.18.30，QQ 为 3.2.32-52194；账号原有持久挂载不变，普通启动继续使用 `pull never`。
- Windows 时间源有效；WSL 与宿主时间一致，不存在 Linux NTP 与宿主持续相互校正。
- 时钟调整不改变 Linux 进程身份；Core 与账号调和器持续运行，状态查询不再因旧墙钟签名失效。
- 已登录账号沿用原缓存恢复，真实 QQ 消息进入正确账号的会话；OneBot 断连后自动恢复，其他账号不受影响。
- 管理台分别显示账号连接、QQ 在线状态与最近事件；超时或离线不能继续显示确定的在线状态。

## 质量标准与验收边界

- 只记录时间、数量、版本、状态和摘要，不记录群消息正文、密码、token 或登录缓存内容。
- 真实消息接收以 NapCat 入站、OneBot 接入和会话持久化证据为准；容器 healthy、头像和 QQ 身份信息不能单独证明可收信。
- OneBot 重连验收不伪称覆盖腾讯强制登录失效。静默离线的 60 秒 Worker 恢复由上游版本提供；真实踢出不人为触发，快速登录被拒绝时仍可能需要扫码。
- 未运行的架构、真实账号或长期稳定性观察必须保留为未验收，不以单次重启成功替代。
