# QQ 登录恢复与运行环境稳定性

## 用户目标与环境

管理员通过管理台查看和恢复阿罗娜、普拉娜的 QQ 连接；后台页面不持续放大查询，重试不重复重建容器，状态查询不能撤销新的重新登录操作。角色为本机管理台管理员，无主对话或外部 Provider。环境为 Linux/WSL Native Core、每账号独立的本地或远端 NapCat Docker。

## 输入与预期结果

1. 对同一账号同时查询在线状态，合并正在进行的读取；稳定在线后不重复写自动登录账号或删除登录文件。账号离线后再次登录仍可完成持久化。
2. 在线状态查询延迟返回，期间管理员开始重新登录；旧查询不能恢复旧自动登录账号、删除新的手动登录标记或二维码，也不能返回成功完成新登录的结果。
3. 并发点击同一账号的恢复登录只执行一次恢复；其他账号独立运行。失败明确报错并保留脱敏操作记录，允许明确重试。登录、退出与账号转移留下不含 token、Cookie、密码和二维码的操作记录。
4. QQ 接入页和离线登录弹窗隐藏时暂停自动轮询，恢复可见时立即核对状态；过期二维码继续遮罩，关闭或切换账号后的旧请求不得覆盖当前页面。用户主动刷新保持可用。
5. 同组连接状态的并发宿主健康查询复用正在进行的探测，并短期复用成功结果；账号连接集合变化不沿用旧结果，探测失败不得伪装成功。
6. 默认每账号使用稳定且相互区分的 hostname，管理员可显式指定固定名称。普通账号重启保留既有容器身份与 QQ 持久化目录；镜像或启动环境确需更新时明确重建。手动登录恢复不能因为保留容器的旧 ACCOUNT 环境而自动回登旧账号。
7. 升级 NapCat 使用经验证的 amd64/arm64 上游镜像摘要。全局登录目录迁移在隔离副本验证，保留现有设备及登录资料；失败阻止部署，不以新空目录替代原资料。
8. 全局目录迁移后，每账号 1 GiB 缓存维护继续覆盖新旧目录中的可重建缓存，登录资料、设备信息和消息库保持不变；双目录并存时计入同一账号总额，不把它们分成两个配额。

## 机械验证与质量标准

使用真实生产登录控制类、管理接口、Vue composable、运行探测与启动器；HTTP、Docker、QQ 文件和账号均为隔离夹具。覆盖迟到查询、并发写入、错误恢复、多账号隔离、隐藏页恢复、二维码过期，以及本地/远程启动参数。独立 fixture Agent 复核断言及操作轨迹，不能以 mock 状态证明真实 QQ 长期稳定。

执行顺序为相关单元测试、独立夹具评审与 harness 自检、runtime contract、类型检查、完整 verify、管理台 light/dark 视觉检查。真实 Provider 无本轮必要性，不外发人格或聊天资料。

## 生产验收边界

部署和重启需另经用户确认。切换前准备代码、数据库及 QQ 登录目录恢复点；Core 更新与 NapCat 更新分开核验。升级后检查容器身份、hostname、镜像、目录迁移、QQ 登录和 OneBot 最新入站，必要的手机登录确认由用户完成。隔离验证不保证腾讯继续接受既有登录态，也不宣称掉线已永久消除。

## 固定设备身份用例

角色为本机管理台管理员，环境包括本地与 SSH 远程 NapCat。输入为管理员保存的固定设备配置：主机名 `Fixture-PC`、合成的 32 位 machine-id、两个账号各自不同的 MAC 与 IPv4。配置与账号无关的 Core、业务数据库和 QQ 登录目录不得变化；本用例不调用外部 Provider，不发送 QQ 消息。

机械验收覆盖：未配置时保持已有启动行为；配置后，两账号在启动、普通重启与重新创建的 Compose 参数中始终取得同样的设备名、MAC、IP 和只读 machine-id 文件；本地与远程生成结果一致。重复准备不能重新分配标识、修改 QQ `machine-info` 或登录资料。两个账号不得共用同网段 MAC 或 IP；错误的主机名、MAC、IPv4、machine-id 以及重复地址必须在执行 Docker 前明确报错。独立 fixture Agent 检查真实启动器调用轨迹和输出文件，不以 mock Docker 证明真实 QQ 登录成功。

生产配置采用实际 Windows 设备名，网络地址记录当前 ECS 容器的独立地址。ECS 与容器 machine-id 不同时，替换会改变 NapCat Linux GUID 的输入，必须取得用户对该身份迁移的选择；禁止静默替换。部署前准备配置和 QQ 登录资料恢复点；容器重建需用户确认。上线后回读主机名、网卡、machine-id、QQ machine-info、登录状态、OneBot 心跳和真实入站，报告真实硬件和闭源 QQ 实现的未验证范围，不宣称容器成为 Windows 设备或保证腾讯永不撤销登录态。

已有网络的子网或网关不匹配时，本地与远程 `up/start/restart` 及运行账号的 `reconcile-account` 均在停服、清理二维码及 Compose 操作前失败，命令轨迹只允许只读查询。停止或删除账号的调和不受此检查阻止。网络尚未创建时，该检查不创建网络；原启动流程在所需阶段按固定子网与网关创建。
