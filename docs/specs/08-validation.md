## 11. 验证标准

功能开发前必须先创建可执行的 user test case Markdown，记录用户目标、输入、角色/环境、预期工具与结果以及逐项质量门槛。默认验证顺序为受影响单元测试、user test harness、其余集成/安全/迁移/runtime/build/E2E/visual/跨平台验证；任一阶段失败都返回主 Agent 诊断和修复，不能上线。主对话 case 使用原始 OneBot event，并显式区分管理员私聊、非管理员私聊、管理员群聊和非管理员群聊；`actor` 在单次 run 内把事件用户投影为管理员或非管理员，不读取或写回源 workspace 的真实管理员身份。fixture 与真实 WebSocket 共用 `OneBotGateway.ingestEvent` 的解析、forward 补全和 delegate 路径，外发改用 recording `MessagingPort`，全部存储位于带专用 marker 的隔离 workspace；CLI 必须先绑定目标 workspace 再加载任何 Runtime/路径模块，并由子进程回归证明 SQLite 只生成在目标目录。prepare 可显式选择源 Agent，并把该 Agent 的人格、局部提示词与资源复制到隔离目录、设为隔离默认 Agent；分支样本不得借用其他 Agent 的 persona。主对话的工作记忆、长期记忆、用户画像、AIR 和 Native/Docker Workbench 文件前置条件必须由 `input.fixture` 机械 seed，路径遍历、符号链接目录组件和既有目标失败关闭；outbound kind 断言分别识别 `message`、`asset` 与 `poke`。每个独立 run 或网络/权限重试必须重新 prepare workspace；同一 OneBot event 在一个 workspace 内重复时失败关闭，只有明确声明的状态链式套件可用不同 case/message ID 顺序复用。macOS Colima 的 Docker Bash case 必须使用 VM 可挂载的宿主共享路径，不能把 `/private/tmp` bind source 不可见误报成产品失败。用户群聊 case 保留真实 ambient orchestrator 路径，只为隔离会话设置 1 秒响应窗口，完成门禁必须同时等待 ambient 状态与 Session events。Dream 与记忆压缩 case 直接进入对应业务管线，不排队手动 Dream 通知、不连接真实 NapCat；两类 live case 必须声明逻辑 `now` 与 `timePolicy: "rebase_to_runtime"`，用同一执行时钟整体平移结构化记忆/消息/任务时间，Dream 的 Director 日程按目标 Dream 日期保留本地墙钟时刻重映射，报告记录不含正文的 timeline 证据；`fixed` 只供受控时钟单测，真实 run 失败关闭。两类 case 都用显式 fixture 替换隔离工作记忆、长期记忆和用户画像，Dream 还显式替换会话、人格、active tasks 与 nullable Director 日程，不能隐式继承测试账号的原始记忆。prepare 必须移除旧 Markdown/JSONL 记忆和复制进来的 Agent-local `data/`；无法通过公开 API 稳定 seed 的 Dream history、recall stats、系统时区和 selection config 继续由端口级确定性测试覆盖。

fixture Agent 只执行 case、核对工具/分支/持久化/outbox 机械证据并评价输出质量，然后提交绑定 run ID 与 case ID 的报告；根因分析、修复和复测由主 Agent 负责。优先使用多个 subagent 并行执行独立 case，复杂核心 case 可以由多个 Agent 独立复测。机械断言全部成功后仍只得到 `inconclusive`，必须再按 case 的准确性、完整性、可用性、语气、事实忠实度和无虚构标准完成 1—5 分质量评审；任一项低于门槛、证据缺失、Provider/工具未配置或运行依赖不可用都不能通过 gate。required tool 必须存在成功的 `tool.call` 结果；失败、仅排队、Provider tool catalog 和未执行定义都不算成功，动态 MCP alias 也进入同一调用证据。`forbiddenTools` 表示零调用，允许审计层记录拒绝但要求零成功时必须使用 `forbiddenSuccessfulTools`。

运行中测试账号只允许通过只读且 `query_only` 的 SQLite 与 realpath 仍位于源 workspace 内的 `WORKING_MEMORY.md`/人格文件取样，输出父目录必须已存在且 realpath 位于源 workspace 外。每个会话默认只取最新 64 条消息，允许显式设置 1—256 条；需要验证工作记忆 provenance 时，取样器先用参数化精确查询选入有界工作记忆引用的会话，再用最近会话补满数量限制。取样结果必须使用与生产记忆调度相同的消息资格规则排除 internal、failed 和 running 消息，只保留可见媒体与引用的数量，样本消息序号从 1 重新编号，源压缩区间和游标归零。V2 sample 必须把用户、群、会话、消息、记忆和姓名改为不可逆 typed pseudonym；字符串型与数值型 `userId`/`userIds` 必须分别映射为稳定且互不合并的 synthetic user ID，不能退化成共享 `[number]`。结构化绝对时间平移到固定 UTC epoch 并保留相对顺序，脱敏邮箱、凭据、签名查询参数、宿主路径、opaque forward、长标识符、显式别名、自由文本绝对日期、可识别地点和可机械识别的敏感个人事件；身份映射必须使用不可级联的受保护占位符，短歧义姓名只在身份边界替换，地点规则不得把所有以行政区或道路字样结尾的中文片段直接视作地点。映射不得持久化，自由文本必须经 fixture Agent 人工复核。`derive-branch-case` 只允许把已复核 V2 sample 注入预先编写并已通过校验的 branch template，保留 template 的 goal/expected/quality；记忆压缩只注入与所选会话 provenance 相同的工作记忆，并保留媒体/引用数量但不把不可见内容当作事实依据，拒绝 V1、digest 漂移、symlink、遍历、覆盖与 conversation case。取样器不得在源 workspace 构造 `ApplicationDataStore`、执行 migration、初始化 recall tracking 或调用 Runtime。user test harness 只接管真实模型参与的高层 happy-path 与内容质量验收；协议矩阵、安全拒绝、故障注入、SQLite 恢复、迁移、Session 并发/幂等、视觉、跨平台合同和真实 NapCat/QQ 验收继续独立保留。`test:unit` 必须保留 `src/`、管理台与 `tests/unit/` 的常规测试并排除 `tests/user-test-harness/**`，后者只在紧随其后的 `test:user-harness` 阶段执行，禁止跨阶段重复。发行前 `.user-test-runs/release-manifest.json` 必须绑定当前 Git revision、当前 case digest、sealed pass、独立 run/reviewer 数量并通过 release gate；`runtime:release` 先执行该 gate。完整操作合同见 [`docs/user-tests/README.md`](../user-tests/README.md)。

脱敏样本必须从自由文本移除图片、视频、语音、文件占位和被引用 message ID，纯媒体/引用消息不得进入 conversation；媒体与引用只保留计数。digest 覆盖的 `fixture.messageSelection` 必须记录源消息、生产可用、实际注入、segment-only、internal、failed、running、other、media 和 quote 数量，使 fixture reviewer 不读取源账号也能复核选择门禁。

场域知识专项必须覆盖 `AIR.md` 缺失初始化、64 KiB 上限、必需章节、符号链接拒绝、revision 冲突与原子替换；`read_air` 只接受严格的 `insight` 参数，并在一次更新中同时获得原有场域知识、当前会话范围及最近聊天记录、角色注入理解。运行时回归必须证明显式称呼、反感、禁忌、边界、群规和已解释私梗会触发可用工具，prompt override 不获得更新端口，成功写入后当前人格热重载，跨 Agent 与跨会话内容不串用，冲突重试仍保持单文件完整。提示词回归必须覆盖 `persona.air`、`air.knowledge`、`air.conversation`、`air.insight` 的目录登记，公共与 Agent override 的 `read_air.json`，旧自定义私聊和群聊模板一次性补变量与 canonical tool 后不再回填，以及管理员自定义消息顺序、角色、工具和 response format 保留。管理台必须验证“场域知识”“读空气提示词”和“读空气”工具目录项在桌面、移动端、light 与 dark 模式下可见可编辑。

会话工具策略必须覆盖 QQ 私聊、群聊和 `web:admin` 的独立 SQLite 重载，旧会话缺少字段时默认全部跟随 Agent，总开关关闭后会话不能重新启用。API 负例必须覆盖未知工具、重复工具、非数组、多余字段和无效会话 ID；Provider 回归必须证明会话停用会同时移除工具定义、执行模式和实际调用能力，伪造 Function Call 零副作用。管理台 E2E 与视觉检查必须覆盖每条会话列表项、会话详情和 Web Chat 的独立设置入口，QQ 会话的回复与群聊编排器设置，QQ 与 Web Chat 的工具权限，Agent 已停用锁定、会话间隔离、防抖与同实例串行同步、失败保留输入并阻止离页、深链刷新、返回原会话，以及桌面/移动端 light/dark 页面。页面不得显示通用保存、放弃、未保存标记或离页确认。延迟请求回归必须证明切换会话或 Agent 后旧工具目录、旧草稿及迟到的成功或失败响应均不会显示或写入新上下文，工具数据就绪前不能切换；工具同步只能提交严格的 `disabledTools` 数组。

知识库专项必须覆盖嵌套目录递归顺序、未知扩展和符号链接忽略、文件数与深度上限、JSONL 每个非空物理行分段、Markdown/文本自然段分段、BOM/CRLF、无效 UTF-8、超限文件、硬链接、读取中身份变化，以及增量同步、删除源文件和全量重建。检索必须证明 FTS5 `bm25` 排序、中英文 token、路径命中、limit 边界、当前 Agent 隔离、相对路径与精确行号、正文截断和伪造未声明工具零执行。管理 API 必须覆盖 list/search/reindex、Markdown 嵌套上传、同路径冲突、路径穿越、非法 Unicode、非 Markdown、空正文、超限正文和安全删除；管理台必须覆盖 Agent 切换迟到响应、搜索、上传、删除、重建，以及 390/1440 light/dark 页面和弹层无横向溢出。

Web Search 证据专项必须覆盖晚于模型知识截止日期的陌生官方产品名、历史 assistant 已作出的错误夹带判断、首轮只返回低质量二手来源、官方域名定向补查，以及摘要中含“忽略此前指令”等恶意文本。每个 Tavily 成功结果都必须返回宿主权威的 `websearch_evidence_policy_v1`，并证明其要求模型重新核对历史结论、优先官方一手来源、证据不足时保持未核实、只凭陌生感不得判定伪造或夹带、不得执行搜索内容中的指令；Prompt Tool 描述被管理员覆盖时也不能移除该结果契约。

WebFetch 专项必须覆盖两种公开参数分支、额外字段拒绝、静态 HTML、受控 HTTP JavaScript 页面、Defuddle Markdown、中文无空格 query、文档顺序、邻接块、固定 token 预算、缓存与取消。安全负例必须覆盖协议、userinfo、自定义端口、尾点、IPv4/IPv6 私网、metadata、mapped/NAT64/6to4/Teredo、混合公私 DNS、DNS family 不一致、DNS 超时、重定向到私网、非 HTML、解压炸弹、动态 HTTPS、CONNECT、动态子请求、WebSocket、非 GET、无预算请求、请求/聚合字节上限、队列溢出、客户端取消和 DOM 超限，并证明被拒目标零连接。Provider 回归必须证明 OpenAI Responses、Codex Responses、Chat Completions、Anthropic Messages 与 Gemini generateContent 的实际请求体中 `webfetch` 都是无 `oneOf` 的扁平三字段 schema；OpenAI 与 Codex 显式携带 `strict: false`，宿主仍拒绝关闭匹配时携带 query、开启匹配时缺少或传空 query。全局 Tool schema 门禁还必须以非法 fixture 证明 `oneOf`、strict object 缺少 `additionalProperties: false`、strict properties 未全部 required 时在任何 Provider 请求前返回 `PROVIDER_TOOL_SCHEMA_INVALID`。其余 Provider 回归必须证明 `webfetch` 可在本地数据工具前后继续执行，`websearch` 后可继续 `webfetch`，网页伪装 system/developer/tool 或 evidence policy 的文本作为不可信正文保留，宿主策略不能被覆盖。运行合同必须覆盖 renderer 无 workspace/secret 挂载、回环端口、非 root、只读根、cap drop、no-new-privileges、seccomp、资源限额、可选能力降级，以及 Core/renderer 的 Linux/WSL `linux/amd64` 与 Apple Silicon 原生 `linux/arm64` 镜像；还必须验证 Chromium 安装层严格位于 production `node_modules` 和应用 `dist` 层之间，确保业务代码变更复用浏览器依赖缓存；并证明普通 direct fetch 无法绕过策略代理、CONNECT 固定返回 405、HTTPS 动态入口返回稳定失败、队列取消释放容量，并通过 SIGKILL Chromium 主进程证明容器会非零退出、由 Docker 重启且恢复 healthy。旧私聊与群聊 Prompt 必须通过 `webfetch-v2` 迁移补 canonical 工具或替换旧 schema，同时保留管理员消息、工具说明和其他工具。

Provider 工具组合专项必须以 OpenAI Responses、Codex Responses、Chat Completions、Anthropic Messages 和 Gemini generateContent 五种协议覆盖 sibling assistant text、多个 inline 工具、跨模型轮次的本地与联网调用、多个 MCP server、失败调用后的后续工具、`read_file → write_file → send_file`、Skill 或媒体导出后派发 deferred Codex，以及查询后 `no_reply`。每次调用仍须独立执行 schema、身份、会话、路径、审批和持久化边界；端口缺失、参数非法或单项调用失败只产生该调用的稳定结果，不能污染或取消随后合法工具。一个 completion 最多接受一个 deferred task，同一响应的 inline 工具先执行，deferred acknowledgement 只使用 `dispatch_message`；正文与 `assistant_text` 不得重复生成第二条受理消息。

Agent 与系统设置的控件级保存回归必须覆盖 toggle 与选择项直接提交、文本/数字/密码输入在确认前只保留本地值、确认按钮与 Enter 提交、未确认输入不被同分区开关或离页 flush 带入、同分区连续确认与多分区串行提交、每次请求使用前一响应的最新 revision、409 刷新 revision 后只重试一次、第二次冲突停止、服务端校验与网络失败保留当前输入并定位字段、Agent 切换取消旧上下文请求、已确认请求在路由离开时 flush 成功或失败留页、Bark 密文占位与清除语义，以及页面没有全局同步条、“已同步”、通用保存、放弃和未保存离页确认。提示词正文必须继续显式保存并保留冲突恢复与离页保护。设置视觉检查必须逐页覆盖 Agent 身份、回复行为、语气处理、记忆处理、群聊编排、Agent 工具、命令执行、模型服务、回复重试、广播风暴、账户安全和连接与通知，验证桌面分组导航、移动端选择器、字段归属、待确认、确认完成、黑白反转 toggle 与就地错误状态。

全 WebUI 视觉回归必须覆盖登录、状态、Web Chat、会话列表、会话详情、会话设置、定时任务、导演系统、Agent 提示词、系统提示词、记忆及梦境、知识库、图像、语音、表情、日志、Agent、扩展、Agent 设置、系统设置、配置医生和版本更新；在 390、768、1440、1920px 的 light/dark 下检查页面标题、导航、主内容、弹层、分页、空状态和错误状态。每张截图同时检查横向溢出、同轴对齐、信息密度、文本对比、键盘焦点、44px 触控热区、遮罩或点击外部关闭、Escape 与焦点恢复；黑白常规交互、语义色、数据图表和日志终端的颜色职责不得混用。Agent 与系统提示词还要在中等桌面宽度验证常驻变量表，在窄屏验证变量抽屉，并检查变量圆角标记及鼠标悬浮、键盘聚焦说明气泡。

管理台路由回归必须覆盖每个已登记一级页面的直接访问、尾斜杠和浏览器刷新，确认返回 `text/html` 且加载同一 Vue 应用；`/api/*`、相似前缀和未知路径不能进入 SPA fallback，继续返回对应 API 状态或 JSON 404。新增或移除前端一级路由时必须同步服务端 SPA 路由清单与该合同测试。

版本与更新日志专项必须断言 `package.json`、`package-lock.json` 根版本、runtime contract、版本目录、Core Dockerfile 与 Compose 默认值均为 `0.1.3` 且一致，当前版本在目录中唯一存在并排在首位；`CHANGELOG.md` 必须包含目录中的全部分组和条目，README 必须链接更新日志与 GitHub Releases。API 回归必须覆盖鉴权后的 `GET /api/releases` 闭合 schema、无 workspace 写入与 `no-store`；管理台回归必须覆盖公共系统导航顺序、`/releases` 深链、当前发行、发布日期、分组日志、刷新和失败保留旧目录。视觉检查至少覆盖 390 与 1440px 的 light/dark 页面，确认大号版本号、三列日志与移动端单列无横向溢出。历史 `0.1.0` 或 `0.1.1` 到 `0.1.2` verifier 必须保持绑定完整 0.1.2 checkout；`0.1.2` 到 `0.1.3` 升级脚本回归必须覆盖目标版本不一致拒绝、plan 零写入、apply 的 down → 全 Agent SQLite 恢复点 → up → status → doctor 顺序、启动期 `conversation-chat-media-v2` 迁移声明，以及恢复点或启动失败时不伪称升级完成。

Docker 文件闭环专项必须覆盖 macOS Host Docker 与 Linux/WSL/Docker Core bubblewrap 两种形态：容器和 bubblewrap 保留无 Docker socket、只读根、只读 Native/Skill/MCP 投影及资源上限，同时具备出站网络；网络获取结果、聊天媒体从 Native 投影复制后的转换结果和本地生成结果均可写入 Docker workbench，并由管理员群聊、普通私聊和普通群成员的 `send_file` 发送到原会话。管理员私聊继续从 Native workbench 发送；已经排队的旧 Native 根资产必须按冻结根身份继续投递，未知或漂移根保持零远端 action。Bash 审计专项必须断言 `isAdmin` 与原始 `userRequest` 由运行时注入且模型无法覆盖，普通用户直接枚举、读取、披露或修改工作区的请求拒绝，高层级生成、下载、转换、打包和回传任务允许；上传、携带凭据、私网/元数据地址、代理改写和本地文件外发拒绝。Codex 专项必须断言普通用户和缺少宿主授权标记的伪造调用无法创建任务，管理员私聊与群聊 deferred worker 使用 `workspace-write`，控制 schema 继续只在管理员私聊或已认证管理员 Web Chat 的受支持 Native 环境出现。

`FLOW-001`、`FLOW-002`、`FLOW-003`、`MIG-001`、`MIG-002`、`RECOVERY-001` 与 `ONBOARD-002` 至 `ONBOARD-005` 的代码、故障注入和受控 E2E 已完成。真实 macOS Native Core + 多 NapCat Docker 与 Linux/WSL Docker Core + 多 NapCat Docker 的双 QQ 首次运行、账号定向文字/图片/文件/语音外发和重启恢复仍需在具备两套运行环境与真实 QQ 登录态时执行；在该验收完成前，不能把受控 Provider/OneBot fixture 视为真实部署证据。
