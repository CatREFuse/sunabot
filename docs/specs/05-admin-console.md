## 7. 管理台

Agent 提示词与系统提示词正文统一使用 CodeMirror 6 单层 contenteditable Markdown 编辑器，默认显示行号，并提供当前行、选区、折叠、搜索、撤销重做、括号匹配、变量自动补全与 Markdown/内嵌 HTML 高亮；编辑区不得叠加透明输入层或文本镜像层。系统提示词的“记忆”分组包含 Dream 的“梦境整理”与 `memory_dream.json`，记忆处理设置页提供直达 `memory.dream` 编辑器的入口。

管理台侧栏分为“Agent”和“公共系统”。Agent 区包含当前 Agent 切换器、Agent 设置、状态、Web Chat、会话、Agent 提示词、记忆、知识库、图像、表情、语音、日志和扩展；公共系统区依次包含系统设置、配置医生、系统提示词和版本更新，配置医生使用独立 `/config-doctor` 页面并位于系统设置下方，版本更新使用独立 `/releases` 页面。Agent 提示词页显示当前 Agent 除 `AIR.md` 外的人格文件和自拍提示词改写，并提供“覆盖系统提示词”开关；开启后同页增加该 Agent 的系统提示词覆盖入口。记忆页以“场域知识”编辑当前 Agent 的 `AIR.md`。系统提示词页提供“读空气提示词”，编辑公共 `read_air.json`，启用覆盖的 Agent 编辑自身私有副本；系统提示词页不显示自拍提示词改写。管理台支持 light、dark 和跟随系统主题，并适配桌面、平板和移动端。切换 Agent 后，会话、Web Chat、图片、表情、语音、记忆、知识库、Agent 提示词、Agent 工具、扩展和 Bot 配置只读写所选 Agent；Provider 与模型目录、共用开关、公共系统提示词和版本目录保持全局一致。Agent 设置与系统设置不显示分区级同步条，也不使用全局设置同步状态：toggle 和选择项变更后立即串行提交，文本、数字与密码输入先保留在控件本地，点击输入框内的确认按钮或按 Enter 后才进入配置草稿并提交；未确认输入不随其他开关提交，离开页面也不写入。页面只在对应分区就地显示保存失败、冲突或重启生效结果，不显示“已同步”、通用保存、放弃或未保存离页确认。提示词正文继续显式保存并保留未保存离页保护，管理员密码、配置医生修复、危险删除和扩展安装等确认型操作继续使用各自的提交或确认动作。群聊编排器设置以秒显示“启动时间”，默认 60 秒、允许 1—3,600 秒，确认后继续写入 `recentMessageWindowMs`，不迁移现有配置格式。群聊会话设置的“回复”分区在编排器开关后提供“编排器时间覆盖”；关闭时不显示响应时间输入并使用 Agent 启动时间，开启后显示“响应时间 / 秒”，允许 1—3,600 秒并随该会话自动保存。回复行为中的“回复模型”与“读图”分别编辑当前 Agent 的主回复模型和独立读图 Provider、模型、推理强度；读图开关关闭时不调用读图节点。回复行为中的“输入防抖时间（秒）”编辑当前 Agent 的 `bot.replyDebounceMs`，默认 5 秒、允许 1—60 秒，确认后热更新；群聊引用过滤名单接受 QQ 号，命中后仅取消引用，不关闭回复。`no_reply` 工具详情与回复行为页的“no_reply 时戳一戳”共同编辑 `bot.pokeOnNoReply`，任一入口切换后另一入口显示同一值。

群聊会话详情的“会话设置”侧栏与完整会话设置页提供同一份编排器时间覆盖配置。侧栏关闭覆盖时隐藏响应时间输入；开启操作保存并回读后显示输入，提交期间锁定相关控件，新的秒数保存后同步刷新当前会话的有效编排器状态。

Agent 设置依次按“身份与回复”“上下文与编排”“能力与权限”组织，系统设置依次按“模型与回复”“安全与连接”组织。管理员 QQ 与管理员称呼只在“Agent 身份”编辑；退出登录只在系统设置页页头出现。桌面端设置导航显示分组、顺序编号、当前项名称与摘要，移动端使用原生选择器、当前位置与摘要；各设置页使用页面说明、字段组标题、分割线和间距建立层级，不嵌套重复面板。

设置页切换 Agent 前必须完成当前 Agent 已确认的串行保存；保存失败时恢复原 Agent 选择并保留输入，同时提供“放弃更改并切换”，成功保存或管理员明确放弃后才以新 `agentId` 建立读取上下文。新 Agent 读取失败时恢复原 Agent 及其配置。连续切换只允许最新序号建立上下文，旧响应不得覆盖当前草稿。一级路由、设置分区与 ECharts 图表按需加载，生产构建生成 manifest 并执行 gzip 预算门禁；初始入口不得重新包含所有页面和图表实现。Overview 使用按 Agent 的汇总计数 API，不为两个计数下载完整会话和图片数组；图片历史只以 SQLite 为准，不在请求路径同步扫描媒体目录。

旧 Agent 配置缺少回复模型、回复推理强度或读图配置时，设置页分别使用 `gpt-5.5`、`medium` 和当前默认 Provider 下默认开启的 `gpt-5.5` 低推理强度读图配置建立本地草稿；加载兼容值不得触发自动保存，也不得使整个设置页进入错误态。

Agent 区的“知识库”页面固定读写当前所选 Agent。页面显示资料文件数、分段数、索引错误数与最近索引时间，支持输入关键词查看 BM25 结果的相对路径、行号、正文和 Workbench 来源，支持递归目录浏览、全量重建、删除资料，以及选择本地 Markdown 文件并填写可嵌套的保存位置后新增资料。列表、搜索和重建使用 `workbench=all` 聚合 Native 与 Docker 资料树；新增固定使用 `workbench=native`，删除按条目来源提交 `workbench=native|docker`，所有请求显式携带 `agentId`。服务端省略 Workbench 时保持 Native 兼容。切换 Agent 时取消旧请求并清空搜索结果与弹层状态，迟到响应不能覆盖新 Agent。上传只接受 `.md` 或 `.markdown`、单文件不超过 8 MiB，同路径已存在时保留原文件并提示冲突；删除使用确认动作。页面和弹层支持桌面与移动端 light/dark，目录层级在窄屏不得造成横向溢出。

所有 toggle 开启时使用前景色轨道，handle 使用当前页面底色，形成黑白反转；关闭态继续使用中性轨道与 handle，禁用态和键盘焦点样式在 light、dark 与跟随系统主题下保持清晰可辨。

Agent 设置的“语气处理”分区独立编辑当前 Agent 的启用状态、分段回复、主模型跟随、Provider、模型、推理强度、Temperature、最大输出 Token 和失败重试次数，并提供 `conversation.tone-rewrite` 的提示词入口；开关和选择项直接热更新，数值输入确认后热更新。“分段回复”仅在启用语气处理后可操作，开启后按 XML 节点发送多个聊天气泡，关闭时保持旧回复显示方式。开启“主模型跟随”后，Provider、模型、推理强度、Temperature、最大输出 Token 和失败重试次数显示主模型的当前配置并禁用编辑；关闭后继续使用该 Agent 保留的语气处理配置。Provider 留空时显示“跟随默认 Provider”，Provider 列表只提供已启用项，模型继续支持目录选择与自定义 ID。旧 Agent 配置或旧管理 API 响应缺少 tone 或 `segmentedReply` 时使用默认关闭配置，设置页保持可用。系统提示词列表包含“语气改写”；当前 Agent 开启系统提示词覆盖后，可编辑对应私有副本，切换 Agent 后配置与私有提示词保持隔离。

Agent 区的“语音”页面固定读写当前所选 Agent。页面顶部提供固定 OpenAI Audio 兼容协议的服务地址、API Key 环境变量名、模型，以及中文、English、日本語三个音色 ID；`PUT /api/voice-provider` 保存配置，`POST /api/voice-service/check` 只检测当前在线连接，不提供本地安装、启动或关闭操作。API Key 值不进入页面或 Profile，检测结果只显示可用性、延迟或固定安全错误。下方提供当前 Agent 的启用开关和默认语言；启用前默认语言必须已有在线音色 ID。每个语言还可独立维护可选音色资料，显示文件名、台词、大小和更新时间，并通过上传弹层选择不超过 8 MiB 的音频和填写 1—1,000 字台词；音色资料不参与当前合成门禁，已启用时也可替换或删除。设置、上传和删除按控件串行锁定，弹层支持关闭按钮、遮罩、Escape、焦点恢复和移动端满宽。页面通过 `GET/PUT /api/voice-profile`、`PUT /api/voice-provider` 和 `PUT/DELETE /api/voice-profile/:language` 显式携带 `agentId`；切换 Agent 时必须关闭弹层、取消旧读取并清空旧 Profile、服务状态、忙碌状态和反馈，旧 Agent 的迟到响应不能覆盖当前页面。

系统设置的“回复重试”页编辑公共 `normalReply.maxRetries`，字段为“失败重试次数”，默认 3，允许 0—10；确认后热更新全部 Agent。系统设置的“广播风暴”页编辑公共 `broadcastStorm` 配置，包含“广播风暴嗅探”“检测窗口（分钟）”“回复次数”“静默时长（分钟）”和“补充嗅探账号”；开关直接提交，其他输入逐项确认。补充账号与已启用 Agent 的 QQ 合并参与检测；两项公共配置均由全部 Agent 共用，不写入单个 Agent manifest。系统设置读取公共配置时不携带 `agentId`，公共分区的更新也走全局配置；Agent 分区的配置更新必须显式携带当前 `agentId`。管理台读取旧版配置响应时，缺失的 `normalReply` 使用当前默认值，不得因新增配置段缺失导致整个设置页进入错误态。

Agent 区另设“定时任务”页面，固定读写当前所选 Agent。页面以表格显示名称、启停状态、cron/once 计划、下一次与上一次触发时间、最近运行状态、投递尝试、下一次重试、最后错误和全部回调目标，并提供“全部”“循环”“定时”“归档”四个页签；四类查询都排除日常导演创建的内部任务。“循环”收纳 cron 计划，“定时”收纳尚未终结的 once 计划，“归档”收纳已完成或失败且不会再次触发的 once 计划。失败运行提供“重新投递”，确认后通过带当前 `agentId` 的 `POST /api/scheduled-tasks/runs/:runId/replay` 复用已生成正文；其他状态不显示该操作。列表通过 `category`、`page` 和 `pageSize` 执行服务端分页，每页固定 20 项；删除或自动清理令当前页越界时，服务端返回最后一个有效页。归档项可切换“永久保留”，未永久保留的归档项在最近一次完成或失败满三天后自动删除任务定义，运行快照继续保留。新建与编辑弹层管理任务上下文、触发计划、既有会话和群聊 @ 对象。重复计划同时提供每隔几分钟、每小时、每天、每周、每月的快捷设置，以及标准五段 Cron 表达式和 IANA 时区输入；单次计划使用明确时间并提交带时区的 ISO 时间。页面通过带 `agentId` 的 `GET/POST /api/scheduled-tasks` 与 `GET/PUT/DELETE /api/scheduled-tasks/:id` 执行 CRUD，通过 `GET /api/conversations` 选择当前 Agent 已有的完整 QQ 会话 ID；更新和删除提交当前 revision，409 冲突保留编辑内容并提示刷新后重试。切换 Agent 时关闭编辑与删除弹层、取消旧请求并清空旧列表，迟到响应不能覆盖新 Agent；页面、表格和弹层支持桌面与移动端 light/dark。系统提示词页同时提供“定时任务回调”入口，用于编辑 `scheduler.cron-callback`。

Agent 区另设独立“导演系统”页面，固定读写当前所选 Agent。页面顶部提供总开关并直接热更新 `bot.director.enabled`；关闭成功后显示“已关闭”，开启成功后显示“运行中”。页面内部提供“每日决策”“计划任务”和“发送会话”三个页签：“每日决策”通过带 `agentId` 的 `GET /api/director/schedules` 按日期倒序分页展示每天最新 revision 的主题、摘要、来源、完整事项、分享时刻、更新时间和时区；已提交的 `character_revision` 可以在当天不再安排分享时保留 0 条分享，历史读取不得因此使整页失败。“计划任务”通过 `category=director` 读取稳定 `director-` 前缀的任务，保留启停、归档永久保留、失败投递重放、编辑与删除能力。“发送会话”读取当前 Agent 的已有 QQ 会话，并通过独立的 `directorEventsEnabled` 开关决定是否接收导演主动分享；旧会话和新会话默认关闭。会话设置的“回复”分区提供同一开关，两个入口读写同一份会话记录。导演任务不再出现在“定时任务”的全部或生命周期页签。直接访问或刷新 `/director` 必须返回管理台 SPA，不能落入 API 404。配置、每日决策与发送会话并行加载时分别接收结果：其中一个请求失败不得丢弃其他已成功读取的状态，配置 revision 未加载前不得提交总开关更新。切换 Agent 时取消旧请求、清空旧决策、发送会话和任务，迟到响应不能覆盖新 Agent；开关、三个页签、决策明细、会话列表、任务表格和弹层支持桌面与移动端 light/dark。

配置医生页面只检查全局 `workspace/business/config/sunabot.json`，进入页面后通过 `GET /api/config-doctor/scan` 显示“配置正常”“发现可修复问题”或“需要手动处理”，并区分本地规则、语法检查和 AI 诊断来源。本地规则以当前规范化配置为目标，为全部缺失字段补入当前缺省值；已有非法布尔值回填 `false`，其他非法字段使用能够通过完整配置校验的空值或当前缺省值，多余字段移除。页面在检查状态栏提供“一键修复”，管理员在确认弹层中查看全部路径、动作、服务端计算的目标值和风险后，通过 `POST /api/config-doctor/apply` 一次应用服务端保存的完整方案；`POST /api/config-doctor/propose` 仍只用于显式 AI 复核本地无法确定的剩余问题。方案绑定源文件 revision、有效期为 10 分钟；配置变化、方案过期或仍有不可修复问题时必须重新检查。页面显示 AI 使用的 Provider、模型和请求目标，应用成功后自动复检并显示持久备份路径；方案内字段会热更新到当前活动配置，磁盘中方案外的合法变更只落盘并提示重启。无法可靠恢复的语法、重复字段、不安全路径、超限结构和未来 schema 版本继续要求手动处理。当前不提供用户主动回滚操作。

版本更新页面通过全局 `GET /api/releases` 读取当前运行实例的版本目录，不携带 `agentId`，也不读写 workspace。页面顶部显示当前版本号、发行状态、名称、摘要与发布日期，下方按版本列出分组更新内容；刷新期间保留上一份有效目录，刷新失败就地显示错误，首次加载失败提供重试。页面使用单层分割线和响应式网格，桌面端并列展示变更分组，移动端纵向排列；light/dark 下都不得出现横向溢出。

Agent 页面以列表和详情双栏管理 Agent，支持新建 Agent、启停、查看隔离 workspace 与新增多个 QQ 账号。Agent ID 创建后保持稳定，名称可以修改；新建非默认 Agent 的自拍提示词使用通用角色模板，默认 Plana Agent 保留普拉娜专用模板。Agent 身份页可上传或更换仅用于管理台展示的 WebUI 头像，支持 PNG、JPEG、WebP，不限制原图文件大小。选择图片后必须通过圆形裁图弹层调整位置和缩放，保存透明圆形头像；QQ 头像保持独立。QQ 容器区使用“新建 NapCat QQ Docker”入口；提交创建时入口和确认按钮显示带旋转加载图标的“新建中”，移除账号时该行显示带旋转加载图标的“移除中”，两种操作均禁用重复提交。新增、启停或移除 QQ 后，由宿主 account runtime daemon 按注册表调和目标 NapCat 容器，Docker Core 通过 workspace request/result bridge 请求宿主执行且不挂载 Docker socket。未运行账号始终显示“运行”，调用单账号启动接口后创建或启动对应 Compose project；成功后刷新为“待登录”，不能要求重启全部 Sunabot。管理台显示期望状态、实际状态、是否仍需调和和最近错误。注册库不可读时调和失败关闭，不能生成停止或删除计划。每个账号独立扫码、退出和打开对应 NapCat WebUI。新账号完成已绑定 QQ 的登录后自动处理旧账号：当前登录必须已确认且不处于手动切换中；旧账号先关闭快速登录，在线连接尝试发送退出动作并断开，再强制重建该账号自己的 NapCat 容器，成功后以单个事务转移 QQ 归属。退出动作失败由容器重建收口；旧账号状态不明、容器重建失败或持久化失败时显示明确失败并保持唯一原归属。Core 启动时只在推断 QQ 尚未归属其他账号时回填 `primary` 身份；旧运行目录中的已转移 QQ 不能覆盖当前唯一归属或阻止 Core 启动。Plana 的 `primary` 是固定基线账号，可以退出 QQ 登录，不能从注册表移除；管理 API 对移除请求返回 `PRIMARY_ACCOUNT_REQUIRED`，管理台不显示移除入口，其他离线账号可以移除。

新增 Agent 弹层支持选择配置文件夹；ZIP 仅作为浏览器无法选择目录时的兼容输入。选择后先预检，展示已包含文件与将由目标当前默认值补齐的缺失项；校验失败会清空载荷，关闭后重新打开不保留预检或错误状态。创建提交仍由服务端重复预检并原子发布，手动上传的 WebUI 头像优先于包内头像。

Agent 扩展管理 API 按当前 Agent 提供 Skill 安装、独立安全审查、启停、卸载、跨 Agent 复制预览与原子应用，以及 MCP server 描述符增删改。`POST /api/agent-extensions/skills/:skillId/review` 只接受严格正文 `{agentId,approve:true}`；管理员 session、CSRF 与 Origin 校验完成后才运行摘要绑定的审核事务，成功后关闭该 Agent 的扩展运行生命周期，失败不改变审批状态。Skill 复制必须显式选择 skip、replace 或 rename，复制普通文件树、重新校验并原子发布，不共享 inode，也不复制 MCP secret 或 OAuth 凭据。MCP runtime API 提供目录读取、显式工具调用、resource read/subscribe/unsubscribe 和 prompt get；全部端点复用管理员 session、CSRF 与 Origin 门禁，使用严格字段集合和请求中止信号。MCP OAuth 授权入口只接受 localhost 回调，展示并绑定当前 Agent、server、resource 和浏览器 session，成功后配置仅保存 credential handle。

扩展页固定使用当前 Agent，顶部汇总 Skill、MCP 与一次性批准；页面先读取 overview，再并发读取 MCP 运行状态与批准队列，避免只读状态调和与 Skill 索引恢复争用同一扩展目录。Workspace 根目录新增或删除无关运行项后，Agent 工具目录、Skill 与 MCP 目录读取必须继续可用，不能把根目录正常内容变化报告为扩展目录替换。Skill 区提供 ZIP 安装、摘要审查、启停、卸载和跨 Agent 迁移，迁移必须先预览再选择 skip、replace 或 rename。MCP 区提供 stdio 与 Streamable HTTP 描述符的新增、编辑、启停、删除、运行状态和目录详情；stdio 参数与环境变量名称逐行输入，保存前完整展示固定可执行文件与参数并显式确认。OAuth 只打开本机受控授权流程，页面只显示绑定状态和刷新、撤销动作；浏览器不保存 secret、OAuth token、宿主路径或凭据值。待批准 MCP 工具调用以有时限的独立队列展示，批准动作绑定当前 Agent 和 ticket。全部危险删除使用确认弹层，错误留在对应页面或弹层内，页面同时支持 light、dark、桌面和移动端。

复制预览返回的 MCP server 已是最终目标安全形态，并明确显示停用与是否需要重新授权；apply 绑定同一 preview revision、源/目标 Skill revision 与源/目标 MCP revision，不能在确认后重新读取并复制源凭据。stdio 复制保留非秘密 env key 名称，以便目标 overview 显示缺失项；管理员重新确认完整命令并替换描述符后解除迁移状态，全部目标 key 配置完成前仍不能启用。Bearer/OAuth 的目标授权状态为 pending 时，启用请求稳定返回重新授权错误；OAuth 绑定成功只替换目标 Agent 的 handle，仍由管理员显式启用。

登录页使用 Sunabot 品牌 Hero 与管理员登录表单组成响应式双栏，移动端按 Hero、表单顺序纵向排列。用户可见文案只保留名称、状态、动作、结果和完成操作所需的提示；页面不得展示鉴权实现、浏览器存储方式、数据来源、区域职责、设计说明或装饰性状态代码。

设置中的 Agent 工具页默认打开“工具目录”Tab，列出二十四个真实工具的图标、名称、Function 名、摘要、配置状态和同步或异步方式，支持搜索、启停与刷新。`read_air` 显示为“读空气”同步工具，并沿用当前 Agent 与会话工具权限开关。健康的运行能力不显示通用状态标记；限定会话的能力以锁图标和中性文案显示适用范围，只有运行环境异常时才以错误语义显示具体原因。`native_bash` 与 `docker_bash` 分为两行，详情分别显示 Native host 或 Docker 强隔离的可用状态、固定会话范围、实际模型描述、描述来源、JSON Schema 参数与严格模式；`no_reply` 详情显示“no_reply 时戳一戳”，`system_config` 显示为内置同步工具。工具启停直接提交；模型描述点击“确认”后建立全局覆盖，“恢复继承说明”会删除覆盖。“运行参数”Tab 继续管理单轮调用上限、Tavily、Codex Worker 和图像生成默认值，选择项直接提交，输入值逐项确认。两个 Tab 共用当前工具配置草稿并按确认顺序串行提交。

Agent 工具页只控制当前 Agent 的工具总开关。每条会话列表项、会话详情页和 Web Chat 页均提供“会话设置”入口，进入可深链、可刷新、可返回原会话的独立设置页；QQ 会话包含“回复”和“工具权限”两个分区，Web Chat 只显示“工具权限”。回复分区编辑当前会话的回复开关，真实群聊同时编辑群聊编排器开关；工具权限分区读取并同步当前会话的工具选择。Agent 已停用的工具在会话设置页锁定关闭；健康的运行能力不显示状态标记，会话范围限制使用中性文案，运行环境异常时显示 API 返回的具体原因并保留会话选择。`activate_skill` 与 `read_skill_resource` 的能力状态只反映运行端口是否接线，空 Skill 目录不显示异常。回复与工具权限共用当前页面实例的防抖串行队列，分区内就地显示等待、同步、成功或失败状态，不显示保存、放弃、未保存标记或离页确认；离开页面先刷新队列，失败时保留输入并留在当前页。工具目录必须在当前 Agent 与完整会话 ID 的数据全部就绪后才能编辑；会话或 Agent 切换取消旧上下文请求，工具同步只提交严格的 `disabledTools` 数组。`GET/PUT /api/conversations/:id/tools` 同时支持 QQ 会话 ID 与 `web:admin`，未知工具、重复项、多余字段和无效会话 ID 返回 400。

Agent 身份页编辑 WebUI 头像、管理员 QQ 和管理员称呼，Agent ID 与工作目录只读展示；回复行为页不重复管理员身份字段，上下文消息数的新建与缺字段默认值为 32，管理员显式保存的 1—120 值继续保留。“记忆处理”只配置 Dream 模型、推理强度与提示词入口；旧的近期窗口、两组选择数量和归档压缩入口不再展示，既有配置字段只作读取兼容且不参与 Dream。记忆页的“立即做梦”在当天完成后保持可用，只在历史加载或本轮触发进行中禁用；触发成功后刷新并显示当天最新运行状态，有效运行仍在时显示 `DREAM_BUSY` 对应的安全错误。工作记忆工具受 `WORKING_MEMORY.md` 64 KiB 文件上限约束，长期记忆和用户画像不设数量上限。Bash 与 Codex 的启停只在工具目录出现；命令执行页只配置对抗审批 Agent 模型与严格审批，固定展示管理员 QQ 私聊和管理员 Web Chat 可使用 Native 与 Docker、其他 QQ 会话只使用 Docker、Skill 与 MCP 配置只读，以及 Native Agent workbench 与 Docker 隔离 workbench。旧 backend 选择、管理员身份门禁、管理员群聊开关、关键字黑名单与 workspace 开关不能作为有效配置展示。`native_bash`、`docker_bash` 与 `codex` 的工具说明允许覆盖，启停状态不能再写入通用工具覆盖。

`native_bash` 与 `docker_bash` 的目录状态按所选 Agent 读取对抗审批 Provider 与各自执行环境 capability；配置启用、固定会话范围和隔离环境状态分开显示。Plana 与其他 Agent 统一通过 Agent 配置服务读写 Agent 级审批设置，管理表单、工具目录和运行时不得读取不同配置源。运行时配置 epoch 变化后，下一次状态查询与下一轮 Bash handle 必须使用同一新配置快照完成审批和隔离探针，旧执行 handle 立即失效。API 目录只返回安全裁剪后的 Native/Docker capability、固定会话范围与稳定原因码，不返回 audit runner、审批上下文、宿主路径或沙箱诊断正文。

状态页使用响应式数据拼盘展示所选 Agent 的 QQ 账号、连接状态、内容计数、Provider 健康，以及当日 Token 总量、输入、缓存输入、缓存率、输出和请求数，并可切换“当前 Agent”与“全部 Agent”。Provider 状态使用统一 probe，显示“已验证可用”“当前不可用”或“未配置”，已保存密钥不能覆盖失败的健康结果。全部 Agent 视图只汇总 Token、请求数、在线 Agent 和在线 QQ 数，不混合展示会话、记忆或人格数据。拼盘保留非对称网格，通过留白、分割线和连续数据区组织信息，不使用圆角卡片逐项装箱。Token 统计使用浏览器传入的时区偏移：当日小时序列固定返回 0—23 点 24 个桶，缺少的小时补零；日视图固定覆盖截至当日的最近 53 周本地日期，缺少的日期补零。用户可在小时图与日历热力图之间切换，并按模型和回答、编排器、记忆、其他功能组合筛选；汇总指标与当前图表始终使用同一筛选范围，未标注模型作为独立选项。小时图使用 Token 总量柱形和缓存率折线，缓存率为 `null` 时显示 `--` 且折线跳过该点。四位到六位主指标使用 K 缩写，百万级主指标使用 M 缩写，千分位精确值保留在主数字的悬停提示中，不在数字下方重复显示。

管理台采用 Nothing 风格的克制工业视觉：light mode 使用温暖白底与黑色前景，dark mode 使用 OLED 黑底与白色前景，两种主题保持同等完整。页面信息区通过留白、连续网格和 1px 分割线建立层级，不使用渐变、装饰性阴影、彩色图标底座或卡片套卡片；按钮、输入控件、消息气泡和必要弹层使用紧凑技术圆角。常规选择、导航和开关使用黑白反转，蓝色只用于文本链接，错误、警告、成功和数据可视化保留语义色。Boxicon 不使用背景、边框或圆形外壳，44px 点击热区保持透明，需要加强层级时直接放大图标。中文页面标题使用 Space Grotesk Variable 与系统中文字体，Doto Variable 只用于品牌主视觉与大号运行数字，标签、编号和元数据使用 Space Mono。

Web Chat 使用固定管理员身份和 `web:admin` 会话，通过 Web delivery adapter 进入与 QQ 相同的 Agent loop、提示词、记忆和同步工具链。每个 Agent 长期复用一套 Web Chat 顺序执行状态，消息 ID 和并发回合不能在 HTTP 请求之间重置；模型调用必须进入该 Agent 的运行上下文，使请求日志与 Token 聚合写入对应 Agent 数据库。Web Chat 回复只能写回浏览器消息流，不能经 OneBot 外发；Web Chat 也不能进入 QQ 会话目录、上线通知或 OneBot 外发目标。当前 Web delivery 没有持久化的异步结果投递目标，因此 Web Chat 不向模型提供 Codex、生图、自拍或语音工具；`system_config` 的设置、状态和已知群聊分页查询可用，群聊分页只读取所选 Agent 的安全字段，修改返回明确的 durable delivery 不可用错误且不得暂存。Web Chat 从发送入口开始使用一份包含队列等待的 600 秒硬期限；客户端断开时取消对应回合，管理 API 进入 `preClose` 时取消全部在途与排队回合，下游忽略取消也不能阻塞 HTTP 或后续顺序队列，取消后的迟到回复不能进入浏览器消息流。发送接口拒绝空白正文和超过 16,000 字符的正文，页面支持 Enter 发送、Shift+Enter 换行、发送中状态、错误恢复、非重叠消息轮询和图片缩略图。

Agent Runtime 关闭或被替换时，Web Chat 与 API `preClose` 使用相同的取消语义收口该 Agent 的在途和排队回合；关闭后的迟到结果不能写入浏览器消息流、会话或下一实例。

日志页按从新到旧提供分页纵向时间轴，并以“全部”“OneBot 心跳”“私聊对话”“群聊对话”“记忆压缩”“记忆记录”“梦境”作为业务节点页签；除 OneBot 心跳沿用最近事件缓冲外，节点分类必须在 SQLite 查询分页前完成。“记忆记录”提供“全部”“工作记忆”“读空气”“用户印象”二级筛选，依次映射 `add_workmemory`、`read_air` 与 `add_user_profile`；历史独立记忆 Provider 调用继续进入“记忆压缩”，当前没有该运行时任务时显示空状态。Responses、Codex Provider、Deferred Codex CLI、Chat Completions、Anthropic 和 Gemini 请求同时显示中文标题与原始 action ID，其中 Codex CLI 使用 `codex.tool.complete`。日志行显示业务节点、结果、尝试序号和重试次数，失败与重试使用红色文字及窄状态条；右侧请求详情按同一 `runId` 汇集并分别显示实际请求体、Tool Call、Provider 返回体和元数据，Tool Call 显示名称、调用 ID、参数与结果。模型响应的统一 `tokenUsage` 使用独立用量条展示，请求、返回和 usage 继续使用递归结构化视图，不能退回整段 JSON 文本。日志页汇总回答、群聊编排、历史记忆调用和其他模型调用的次数与 Token；`add_workmemory` 与 `add_user_profile` 属于主回复工具循环，不显示为额外模型调用。非私聊会话详情显示会话累计消息数、当前保留消息数、可见消息数、用户消息数、回答数、内部消息数，以及同口径模型调用统计；页面可见且会话已选中时每 10 秒刷新统计。会话请求日志侧边栏提供本地全文匹配，按不区分大小写的子串同时搜索当前已加载日志的 action、模型、请求体、响应体和元数据，显示匹配数并保留递归结构化结果；未命中时显示“没有匹配的请求日志”。Bot 消息气泡显示消息来源、本轮实际工具和请求日志入口，工具图标不使用背景或边框，窄屏时允许整行换行。记忆页一次只查看一个来源；工作记忆直接显示当前 Agent 的完整 Markdown 阅读原文，长期记忆和用户画像使用一条命令栏在本地筛选与语义召回间切换，并在同一区域完成搜索、排序和结果状态反馈。两类列表按每页 20 条分页，超宽屏在右侧常驻显示选中记忆的详情、元数据与编辑删除动作，较窄视口点击行后使用满宽侧栏；新增弹层固定绑定当前页来源，不能创建工作记忆。语义召回明确显示已提交查询、结果数、输入已修改状态和“返回全部”，请求绑定当前 Agent 与来源，Agent 或来源变化时取消旧请求且迟到响应不得覆盖当前结果；新增、编辑或删除期间发生 Agent 或来源切换时，完成响应不能重新加载旧上下文或在新上下文显示完成状态。切换来源、搜索方式、筛选词或排序时回到第一页，删除后当前页超过有效范围时回到最后一个有效页。系统提示词与人格提示词共用同一变量表交互：中等宽度桌面在编辑器下方常驻显示，超宽屏显示为可调宽度的右侧栏，窄屏通过抽屉打开。变量标记使用清晰的圆角、描边和底色；鼠标悬浮或键盘聚焦时显示包含完整说明、类型与来源的气泡，点击仍在当前编辑位置插入变量。提示词编辑器同时提供已使用变量状态、可选 XML 包装，以及离开前保存；私聊和群聊回复都包含 `conversation.voice.settings` 与 `conversation.voice.trigger_policy`，管理员可直接编辑变量所在消息的角色、位置与包装。Function Tool 的描述编辑器使用同一变量插入和 XML 包装控件，使 `send_voice_message` 的配置说明与运行时变量保持可编辑。已登记变量引用复用 inline code 的底色与文字样式，未登记变量保持普通文本样式；XML 标签中的 `s-if="..."` 条件属性与表达式使用独立语法高亮，但浏览器只显示和编辑文本，不执行表达式。编辑器的可见文字只由单一内容层绘制，选区层只绘制背景，不得生成第二份文本。

记忆页顶部将“工作记忆”“长期记忆”“用户画像”“场域知识”“梦境”作为五个具有 `tablist/tab/tabpanel` 语义的平级页签，使用 roving `tabindex`，支持左右方向键、Home 和 End，并以当前来源真实数量作为唯一大号指标；390px 窄屏下五个页签必须完整可见，不能把末项裁切在视口外。场域知识直接编辑当前 Agent 的 `AIR.md`，保留 revision CAS、刷新、撤销和显式保存；切换 Agent 时清空旧内容，迟到响应不能覆盖当前 Agent。工作记忆页只显示刷新动作、文件名、revision 和当前 Agent 的模型自然语言原文，保留模型给出的段落、空行和 Markdown，只隐藏机器 metadata 注释，不显示宿主事项 ID、记录时间、会话来源、来源类型、排序、搜索、语义召回、分页、新增或逐条编辑删除。长期记忆与用户画像默认按更新时间逆序，排序先于分页执行，切换字段或方向时回到第一页，无有效时间的记录始终位于末尾且保持原顺序；长期记忆以正文和召回统计为主，用户画像以头像、昵称、称呼和 QQ 身份为主。选择“梦境”时以当前 Agent 最近一次运行的状态、下次计划、梦境正文、工作记忆压缩数量和长期记忆新增数量为主内容，历史固定按最新优先排列，并隐藏普通记忆操作。梦境历史最多返回 30 条，前三条直接显示，其余历史按需展开；原因、内部推理、旧的合并、归档、转存和人格变化摘要不再展示。工具区提供“立即做梦”和刷新；触发期间按钮显示“做梦中”并禁用。`POST /api/memory/dreams/trigger?agentId=<id>` 和 `GET /api/memory/dreams?agentId=<id>&limit=<1..100>` 保持既有 Agent 路由、当日唯一、在线账号、迟到响应隔离和下一次 04:00 合同。

记忆页不显示“24 小时处理成功率”或“待处理”状态；系统没有主对话记忆待处理队列。操作日志继续展示两个记忆工具的 record、skip、失败和未完成决定，以及管理员 CRUD、召回与 Dream 操作。

Dream 历史对输出合同失败显示当前尝试次数、固定上限 3、下次重试时间与安全错误。仍可自动重试时显示“输出格式未通过 · 第 N/3 次 · 等待重试”；第三次失败后显示“Dream 输出格式连续 3 次未通过”，不得展示模型原始输出、Provider payload、秘密或宿主路径。其他 Dream 状态、摘要和人工恢复入口保持现有合同。

记忆页首屏密度以完成浏览和定位任务为准：数量与单位同行显示，不能重复占据独立大区块；工作记忆显示短 revision，并通过标题属性保留完整 revision，正文限制阅读行宽；窄屏页头将操作日志收为保留无障碍名称的图标入口，新增与刷新仍保持清晰可操作，命令栏固定为“方式与排序、搜索”两层。长期记忆摘要最多三行、用户画像摘要最多两行，列表可见文本不得显示 `#long_term_*`、`#user_profile_*` 或任何完整内部记录 ID，完整编号只保留在唯一的行按钮无障碍名称与详情面；桌面详情列需要维持可连续阅读的正文宽度。桌面宽度可以默认选择当前页第一条记录以填充常驻详情；窄屏在用户点击前不得预选或高亮首条记录，关闭移动详情后列表也不得保留误导性的选中态。桌面详情列和移动详情侧栏必须建立完整横向收缩边界，正文、记录 ID、起止时间与召回信息允许在自身内容列内换行，关闭按钮、底部操作和任意子元素均不得扩大详情容器的横向滚动宽度。

记忆页的信息密度、表格与详情列参考概念图见 [`memory-tab-concept-2026-07-25.png`](../design/assets/memory-tab-concept-2026-07-25.png)；实际交互、字段和响应式行为仍以上述当前规范为准。

记忆页页头始终提供“操作日志”入口。日志使用右侧抽屉和无卡片时间线，首层显示所选 Agent、记忆类型、操作、执行者、结果、时间、会话来源和数量变化，原因码、batch、record 与 revision 在“技术信息”中展开；支持刷新和分页。点击遮罩、关闭按钮或 Escape 均可收起，切换 Agent 时立即关闭、清空旧日志并取消旧请求。

会话列表与详情的标题来自当前会话所绑定 QQ 账号的好友或群目录显示名；多 Agent、多 QQ 之间不能复用其他账号的备注或目录结果，Core 重启后继续读取按账号隔离的可重建目录缓存。所有新会话默认关闭回复，首条入站消息先建立会话记录并遵守关闭状态，管理员开启后才创建回复任务；已有会话保持原回复状态。保存“启用”或“编排器”只更新开关字段，不得用运行时持久化记录覆盖标题、群名、昵称或备注。

会话详情使用一体化标题栏组合会话身份、标题、回复与群聊编排开关、Token、消息数、编排器窗口和工具入口；开关位于标题下方，设置、刷新和请求日志固定在最右工具区。Token 每满或进入下一个 1M 显示一个连续计量格，消息每满或进入下一个 100 条显示一个连续计量格，格数不设展示上限；编排器窗口把实时秒数、点阵上限、状态和竖条进度放在同一 widget，达到上限后显示值封顶并进入判断状态。编排器在回复关闭时保留显示并禁用，窗口 widget 同步显示关闭并停止计时。完整模型、行为、记忆与消息统计点击 Token widget 后在右侧栏展开，不常驻占用消息空间。标题栏按自身可用宽度响应式重排，中间宽度弹性收缩，窄屏改为标题工具区与三项数据区上下两层，不能裁切右侧 widget 或产生页面横向滚动。会话设置也使用右侧栏，包含回复控制、会话信息和工具权限；回复与工具开关点击后立即同步并生效，工具权限继续受 Agent 总开关约束。设置栏与 Token 详情栏的关闭按钮都位于左上角；侧栏支持遮罩关闭、Escape、焦点恢复和移动端满宽适配。

图片列表和会话正文先读取 48px 低质量 WebP 占位图并以高斯模糊显示，再淡入 480px WebP 展示图；用户打开预览或原图链接时才读取完整图片。生成历史使用紧凑响应式网格，移动端 2 列，随后随视口扩展为 3、4、5、6 列。浏览器缓存已加载资源，图片历史在短期页面切换中复用，返回图片页不重新批量请求占位图和历史数据。

图像页的自拍参考区按当前 Agent 同时显示 Native 与 Docker 素材及来源，每个 Workbench 最多 9 张，每次自拍选用 1–3 张；不得再用独立主管理弹层重复展示同一图库。素材在移动端、平板和桌面端分别使用紧凑的 3、6、9 列，以备注作为主标题，保留文件名、尺寸和大小作为次级信息；添加图片固定进入 Native 标准位置并逐图填写备注，编辑、预览和删除从对应素材就地发起并保持原 Workbench。多选上传必须先为每张图片填写备注；备注的原始输入先拒绝 C0/C1 控制字符（含首尾 Tab、CR、LF）和孤立代理项，再执行 NFC 规范化与 trim，最终要求 1—120 个 Unicode code point；已有备注可以单独编辑。自拍参考 API 接受 `workbench=all` 聚合读取，接受 `workbench=native|docker` 选择独立清单，省略时保持 Native 兼容，返回的原图、展示图和占位图 URL 绑定相同 Workbench。切换 Agent 后列表、上传、修改、预览和删除请求全部切换到所选 Agent，light/dark 与窄屏页面和必要操作弹层均不得横向溢出。

表情页按当前 Agent 分为“预设表情”和“自定义表情”，使用 96px 预览的紧凑横向列表并显示已安装数量、Native/Docker 数量与每项来源；同 key 在两个 Workbench 中分别展示。每项可一键生成、点击或拖入图片上传/替换、就地修改 key、查看历史版本和删除，缺少图片的预设 key 直接显示一键添加入口，自定义 key 在新增弹层中校验。新增、缺失预设的一键生成和上传固定写入 Native，已有条目的替换、改名、版本读取和删除保持原 Workbench。单个 Agent 每个 Workbench 最多 64 个表情，上传限制为 8 MB 的 PNG、JPEG、WebP 或 GIF，生成时缺少自拍参考图、Provider 不可用、同 key 正在生成、规范化繁忙或图库已满都显示对应结果并允许安全重试。表情 API 接受 `workbench=all` 聚合读取，接受 `workbench=native|docker` 选择独立清单，省略时保持 Native 兼容；当前与历史内容 URL 同时绑定 `agentId`、文件名版本和目标 Workbench。每个 key 最多保留 20 条内容寻址版本记录；当前版本不能从历史弹层删除，删除旧版本只移除图库历史元数据，底层内容文件继续保留供已进入 durable outbox 的消息发送。列表先读取 32px 占位图，再读取 640px 展示图，打开原图时才请求完整 PNG/GIF；同 key 替换后 URL 必须变化，旧版本只返回对应旧内容，不能在 immutable 缓存期展示错误图片。管理员可为当前 Agent 选择 64、128、256、512 或 1k 的发送尺寸，并通过“表情单独发送”开关选择随正文发送或紧随正文另发一条消息；两项设置均立即提交、按 Agent 隔离，默认尺寸 512、默认随正文发送。运行时只缩小经过摘要校验的原图并按内容摘要复用缓存，GIF 缩放后继续保留动画。管理台只把每次 mutation 的响应作为操作成功确认，随后以当前 Agent 的 `workbench=all` canonical GET 刷新列表；切换 Agent 或后续请求开始后，旧 mutation 和旧 GET 的晚返回都不能覆盖新状态。删除使用确认弹层，版本历史、编辑和删除弹层支持遮罩、Escape、焦点恢复、light/dark 和移动端满宽布局。

QQ 登录由管理台按 Agent 和账号完成：容器未运行时先显示“运行”，启动成功后显示“登录”；离线时直接显示对应 NapCat 的当前二维码并每 2 秒拉取新状态，二维码轮换后页面自动替换；用户可以主动刷新二维码。在线时显示当前账号并提供带确认的退出操作，退出后对应 NapCat 自动回到扫码态。NapCat 报告 `KICKEDOFFLINE` 时，后端覆盖可能残留的 OneBot 在线信息，将账号视为离线并只强制重建该账号容器；弹窗显示“正在恢复登录”，不展示原始下线通知，轮询获得新二维码后自动进入扫码态。扫码成功后 Core 把 QQ 号写入 `agent_accounts`，NapCat 把快速登录账号写入该账号目录的 `account.env`，并清理临时二维码和手动登录标记，后续重启恢复快速登录。原生 WebUI 只保留为故障诊断入口。

管理台页面脚本随主应用一次加载，路由切换不得再请求页面脚本分块；鉴权启动期间使用统一加载状态。所有已登记管理台页面均支持直接访问和浏览器刷新，服务端只对精确的 SPA 页面路径及其子路径返回 `index.html`，`/api` 与未知路径继续返回对应 API 响应或 JSON 404。主题预加载使用同源静态脚本并在应用脚本前执行，保持 `script-src 'self'` 且不依赖内联脚本；字体与图标由构建产物本地提供，字体保持独立同源资源，不内联为 `data:`，也不依赖外网字体服务。带内容哈希的构建资源使用长期缓存，入口 HTML 禁止长期缓存。浏览器不得因等待脚本或原图而表现为点击无响应。

管理 API、生成图片和管理台数据使用管理员账号密码建立的 HttpOnly 会话鉴权；Cookie 最长保留 30 天，空闲 7 天失效，服务端以 SHA-256 哈希在主库持久化会话，Core 重启后继续识别。写操作还必须通过 CSRF 与 Origin 白名单校验。设置页提供管理员密码修改，成功后轮换当前 Cookie 与 CSRF Token、清除其他会话并保持当前浏览器登录。Bearer Token 仅用于受控自动化客户端，本机回环请求不绕过认证。远程入口包含单来源锁定、全局自动熔断和文件型手动熔断。远程图片代理必须执行协议、域名、DNS、重定向、响应类型、content-length、总字节数和超时校验；生产默认使用系统 DNS 解析并在每次重定向前复验，实际 HTTP(S) 连接通过专用 dispatcher 固定到本次已经验证的地址，重定向会销毁旧 dispatcher 后重新解析，不能在校验与连接之间再次使用系统 DNS。测试替代解析与固定传输只能通过显式依赖注入，解析为空、失败或包含未受信私网地址时必须在请求前失败关闭。

`/design-demo` 是 Quasar 风格的管理台视觉验证页，不进入正式导航，也不读写业务数据。页面复用现有 AppShell、管理员鉴权、主题持久化、Space Grotesk 与 Boxicons，只在页面根节点内使用 zinc 灰阶、蓝色选择态、24/16/12/8px 圆角层级、0.5px 输入描边、单层阴影、快捷入口和分段控件。`/design-demo/settings` 使用同一页面的路由层级状态，前进从右侧进入、返回从左侧进入，位移 120px、持续 125ms；减少动态偏好时取消位移。动态鼠标只在精细指针且未启用减少动态时生效，在操作控件、文本输入和普通画布间分别显示圆环、文本光标和圆点，粗指针与页面离开后保持系统鼠标。页面必须通过 390、768、1440、1920px 的 light/dark 独立视觉用例、无横向溢出检查、分段控件单测、类型检查和生产构建；通过视觉审批前不得把局部蓝色 Token 或自定义鼠标提升为全局管理台默认。
