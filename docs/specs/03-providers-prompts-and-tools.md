## 4. Provider、提示词与工具

### 4.1 Provider

Codex 订阅的实际 Provider 请求优先读取 workspace 标准授权文件并执行受管续期；标准授权不可用时才回退到 Provider 配置的环境变量令牌。

Provider 类型包括 Codex 订阅、OpenAI 官方、Anthropic 官方、Gemini 官方，以及 OpenAI、Anthropic、Gemini 三种兼容协议。类型在创建时确定，创建后不可切换；官方地址由前后端共同固定，兼容地址可配置。Codex 订阅访问令牌临近过期或已经过期时，Provider 调用与运行探针必须通过 Codex app-server 的 `account/read` 管理接口请求续期，同一授权文件的并发续期合并为一次，续期失败按凭据不可用处理，不能自行调用未公开的 OAuth 端点。Provider 支持远程拉取模型 ID 或自定义 ID，多模态能力可通过已知颜色图片的实际识别结果自动探测，也可手动指定。Provider 页面只管理连接、模型目录和能力；当前 Agent 的回复模型、推理强度以及独立读图 Provider、模型和推理强度位于 Bot 设置的“回复行为”。每张入站图片在主回复前由读图节点生成一条有界中文 alt text 并持久化到消息记录；纯文本主模型使用该文本理解图片，多模态主模型同时获得图片与 alt text，以便先判断是否需要通过媒体句柄取得原图。远程图片与受控本地图片进入文本模型或独立读图 Provider 时使用预览输入归一化合同：单图最多 8 MiB、最长边 2,048、最多 16,000,000 像素，超过原始输入门禁或无法安全解码时不进入请求。`generate_img` 与 `selfie` 的参考图使用独立合同：聊天图片先以原始字节写入内容寻址归档，图像 Provider 请求从该原件派生单图最多 16 MiB、最长边 3,840、最多 8,294,400 像素的高保真 JPEG 或 PNG；派生只存在于请求管线，不覆盖归档原件，也不复用文本读图预览。无法安全解码或超过 64,000,000 输入像素的图片不进入生图请求。单张读图失败只缺失该图的 alt text，不阻断其余图片和主回复，也不能改写之后由媒体句柄选中的生图归档原件。配置还包含图像模型、API key 环境变量、温度和输出 token 上限。每次模型传输的实际请求体与 Provider 返回 payload 都写入请求日志，使最终提示词、消息、工具定义和原始返回结构可以倒查；模型 payload 的单字符串最多保留 8 MiB，其他日志继续使用常规长字符串边界。密钥、授权字段和 URL key 必须递归脱敏，`read_file`、`write_file`、`add_workmemory`、`add_user_profile` 与 MCP 的参数、结果使用专用安全投影，不能因记录原始 payload 暴露文件正文、工作记忆正文、用户画像正文、称呼数组、外部 MCP 文本、宿主路径或 token；两个记忆写入工具只保留 action、已知参数键、未知参数数量、正文字符数、称呼数量、成功状态、已知稳定错误码和去重状态，模型正文、称呼值、未知参数名、任意错误码与错误详情不落模型请求、响应或工具调用日志。Gemini API key 只能通过请求头发送，不能进入 URL。SDK 隐式重试必须关闭，发送请求与读取响应正文属于同一次显式传输尝试，正文断流按真实尝试记录并重试；由 `fetchTextWithTransportRetry` 管理的单次传输默认最多等待 60 秒，调用级内部预算可以显式覆盖，未指定调用级重试次数时仅在调用方仍有效的情况下重试一次，调用方取消不能触发重试；取消信号在写入请求日志前检查，429/5xx 退避优先遵守 `Retry-After` 或 `Retry-After-Ms`。Dream、Director、Tone、主动群聊编排、AIR、自拍提示词改写、读图、配置智能诊断、Bash 审计、异步图片生成、在线语音合成及模型返回型健康或能力探针统一由所属任务共享 10 分钟总预算，单次模型传输上限同步为 10 分钟；Director 缺失日程与修订、自拍改写与生图、生图参考预处理与全部重试都不能重新取得第二份预算。QQ 与 Web Chat 主回复、入站读图准备的固定外层期限同为 10 分钟，异步 Session actor 额外保留 5 秒终态结算时间；服务停止、会话失效、任务替换和显式取消仍可提前结束。普通主回复 Provider 继续使用自身重试与传输尝试规则，模型目录 HTTP、文件读取、下载、解析、工具执行和 outbox 继续使用各自边界。

正常回复的每轮 Provider 请求使用公共 `normalReply.maxRetries`，值表示首次失败后的额外重试次数，默认 3、允许 0—10，因此默认最多执行 4 次相同请求。该设置热更新并由全部 Agent 共用，只作用于 `replyToIncoming` 的普通回复、群聊总结和异步结果回复，不改变编排器、记忆、生图、工具任务、outbox 或 Provider 健康检查的重试策略。显式请求必须复用同一请求体，只重试网络错误、正文读取错误、408、409、429、5xx，以及 Codex Responses 在 HTTP 200 流内返回的过载、限流、服务不可用、临时错误或超时；调用方取消、确定性响应体错误或其他非重试状态立即停止。响应体错误必须使用 Provider 原始 message 上报，不能降格为“模型没有返回可发送内容”。每次真实尝试分别写入请求日志，并记录当前尝试序号与最大尝试次数。

Provider 请求使用应用启动时安装的统一出站 dispatcher。显式代理和标准代理环境变量从 `workspace/secrets/runtime.env` 或进程环境读取；WSL 自动模式仅在没有显式代理时探测当前默认网关。代理选择不改变 OneBot 的 Compose 私有网络或同机宿主网关链路。

配置医生的 AI 诊断只在管理员显式请求时使用当前运行配置的默认 Provider，单次调用不提供任何 Function Tool，不执行多轮工具循环，并以严格 JSON Schema 请求结构化的 `add`/`replace` 建议。调用关闭 SDK 级重试，使用 `config_doctor` 阶段和提示词家族写入请求日志；服务端仍会重新解析、校验并按固定字段白名单过滤模型输出。AI 建议只补充本地规则尚未覆盖的允许字段，不能修改 `schemaVersion`、Provider、身份、路径、凭据或其他受保护配置，也不能直接写入配置文件。

OpenAI 官方 Responses 与 Codex Responses 请求必须携带稳定、不可逆且不包含明文身份的 `prompt_cache_key`。缓存键绑定 Provider、模型、行为、提示词家族、记忆类型、稳定 system/developer 前缀、完整工具定义和输出 schema；经验证支持稳定前缀缓存且实际存在静态前缀的模型按该前缀跨会话复用，其余请求继续包含完整会话 ID。同一工具循环的多轮请求复用同一个键。OpenAI 兼容协议不强制注入该字段，避免不支持扩展字段的服务拒绝请求。

GPT-5.6 及后续支持该协议的 OpenAI 官方 Responses 请求必须在最后一段前导静态 system/developer `input_text` 上设置显式 `prompt_cache_breakpoint`，并保留 Provider 默认的最新消息隐式断点。当前 Codex Responses 后端拒绝 `prompt_cache_breakpoint` 和 `prompt_cache_options`；GPT-5.6 及后续 Codex 请求不发送这些字段，将原有合并后的 system 文本映射为首个 developer input，不再同时发送 `instructions`，仅使用 `prompt_cache_key` 与精确前缀参与后端隐式缓存。原有非 system 输入的内容与顺序、工具定义和输出 schema 保持不变。旧模型、未知模型和兼容 Provider 不发送显式断点字段。静态前缀变化时缓存键自动变化；动态历史、召回记忆和当前输入不能进入稳定前缀哈希。

单聊、群聊与 Tone 的默认 system 只保留角色规则、稳定人格、输出合同和运行时静态规则。`runtime.address_rules` 明确要求用户画像存在多个 `addressNames` 时优先使用数组中的第一个称呼，只有当前语境明确需要时才使用后续称呼；该规则不重排、不删除称呼，也不改变 QQ 身份绑定。`persona.air`、工作记忆、长期记忆、用户画像、表情与语音快照、导演行程、群聊编排结果、当前时间和当前输入都必须位于 system 之后；对话模板按“历史消息、低频配置、每日行程、每轮群聊上下文、AIR 与召回记忆、当前时间与输入”的顺序组织。单聊和群聊主回复默认使用 `message_32` 结构化消息组，在独立 4,096 Token 上限内读取当前输入之前最近最多 32 条模型可见历史；默认 `bot.contextMessageLimit` 同步为 32。`messages_64` 继续注册并由运行时提供，只服务于尚未迁移或管理员后续主动恢复的旧自定义模板，并保持原 2,048 Token 上限。既有公共与 Agent override 单聊/群聊模板先通过 `conversation-cache-layout-v1` 保留式整理缓存布局，再由 `conversation-message-32-v1` 只把独立的 `@{messages_64}` 消息组改为 `@{message_32}`，保留管理员消息、角色、顺序、工具、response schema 与额外根字段；使用 `conversation.messages` 或没有旧消息组的模板不补入第二份历史。

模型响应日志保留 Provider 返回的原始 usage，并在日志顶层写入统一的 `tokenUsage`。`tokenUsage` 字段为 `input`、`cachedInput`、`cacheRate`、`output` 和 `total`；日、小时聚合桶在此基础上增加 `requests`：

模型调用通过 `metadata.stage` 归入 `reply`、`orchestrator`、`memory` 或 `other`。`working_long_term` 与 `user_profile` 只用于兼容既有独立记忆 Provider 统计；新的 `add_workmemory` 与 `add_user_profile` 决策属于同一次主回复 Provider 工具循环，不建立独立记忆模型请求或额外统计调用。一次 Provider 请求只计入一个行为类别；没有 usage 的失败请求仍计入调用次数，每次实际传输重试分别计数。Deferred Codex 和自拍改写必须保留完整会话、行为阶段和尝试次数上下文；Dream 运行日志同时保留当前 `attemptCount` 与固定 `maxAttempts=3`，供管理台显示实际重试次数。请求日志写入时同步更新当前 Agent 数据库的 `model_call_aggregates` 与 `model_call_model_aggregates`；前者保存该 Agent 全模型总量，后者按 `conversationId`、模型、行为和记忆类型聚合。单 Agent 统计只读对应业务库；全部 Agent 统计汇总各 Agent 聚合结果，不合并会话或记忆。群聊统计使用完整 `conversationId` 读取精确聚合行，不扫描历史日志。管理台模型调用区支持在全部模型和单个模型之间筛选，调用次数、Token 总量、行为分类和记忆分类必须使用同一模型聚合结果；缺少模型 ID 的历史调用统一显示为“未标注模型”。

- OpenAI Responses/Codex 使用 `input_tokens`、`input_tokens_details.cached_tokens`、`output_tokens` 和 `total_tokens`；Chat Completions 使用对应的 `prompt_tokens`、`prompt_tokens_details.cached_tokens`、`completion_tokens` 和 `total_tokens`。输入总量已经包含缓存输入，不能重复相加。
- Deferred Codex CLI 进程实际启动后，无论完成或失败都以 `model.response`、`codex.tool.complete`、`codex-cli` 写入请求日志；usage 可用时使用 `input_tokens`、`cached_input_tokens` 和 `output_tokens`，其中缓存输入是输入总量的子集，总量由输入与输出相加。终态写入竞争、迟到返回和失败状态不能丢弃已经产生的 usage，同一任务尝试只能统计一次。
- Anthropic 输入总量是 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`，其中只有 `cache_read_input_tokens` 计入 `cachedInput`；缓存创建属于输入消耗，不属于缓存命中。输出使用 `output_tokens`，总量由输入与输出相加。
- Gemini 输入使用已经包含缓存内容的 `promptTokenCount`，并累加 `toolUsePromptTokenCount`；缓存输入使用 `cachedContentTokenCount`，输出是 `candidatesTokenCount + thoughtsTokenCount`，总量优先使用 `totalTokenCount`，小于归一化输入与输出之和时回退为后者。
- `cachedInput` 是 `input` 的子集，不额外计入 `total`。只有 Provider 明确返回缓存字段的记录才进入缓存率分母；单条记录或聚合桶的缓存率为这些记录的 `ΣcachedInput / Σinput` 并限制在 `0..1`。明确返回缓存字段但分母为 0 时返回 `0`；桶内全部记录都没有缓存字段时返回 `null`。缺失、负数和非有限数按 0 处理，任何 API 与界面值都不能出现 `NaN` 或 `Infinity`。

### 4.2 最终提示词

入站图片的 alt text 是与媒体句柄对应的可检索简要语义，所有主回复模型都会接收；多模态模型仍保留原图输入，只有需要核对视觉细节时才通过句柄取得原图。

图片记忆必须先用 `export_chat_media` 取得本轮授权图片，再由获准的 Bash 将图片与可检索说明放入当前 Agent 的 `knowledge/`；说明文件使用指向同一知识树图片的真实 Markdown 图片链接，`add_workmemory` 正文只保存带且仅带一次 `knowledge/` 前缀的 Workbench 根相对链接，该链接之后可直接交给 `send_file`、`generate_img` 或 `selfie`。

`generate_img` 和 `selfie` 遇到用户要求生成特定人物、影视或动漫角色、某个非公共物品，而当前上下文没有足以确认其外貌的真实图片时，必须先通过 `webfetch` 或 `knowledge_search` 找到参考图，并把实际参考图片路径作为必要输入。Native 知识资料的 Markdown 图片链接先相对来源文档解析，再添加一次 `knowledge/` 得到 Workbench 根相对路径；正文明确给出的 Workbench 根相对路径原样使用。两者都要由 Bash 精确核验后再调用图片工具。只找到文字资料、只凭名称推测外观、重复添加前缀或未核验猜测路径时不能调用生图；联网图片需要先由获准的 Bash 保存到当前 Agent workbench。

最终提示词使用 JSON 文档，支持：

- 多条 system、user、assistant 消息；
- 变量槽位；
- 消息正文与提示词片段支持 `<tag s-if="TS 布尔表达式">内容</tag>` 条件注入；表达式只接受变量、boolean/string/number/null 字面量、`!`、`&&`、`||`、`==`、`!=`、`===`、`!==`、同类型数值/字符串比较与括号，不执行函数、赋值、属性写入或任意代码。真分支保留原标签并移除 `s-if` 属性，假分支连同标签和全部内容完全移除；条件裁剪先于普通变量解析，因此假分支内变量不要求存在。条件变量按 Prompt Catalog 的扁平变量名解析，opaque 用户输入、历史消息和运行时正文中的相同文本不得执行；非法表达式、重复属性或缺少闭合标签在保存或渲染时返回稳定模板错误；
- 所有提示词模板都可使用 `bot.name`、`user.name`、`runtime.current_time` 和 `utils.roll` 四项通用变量；`user.name` 仅在私聊回复中提供当前用户显示名，其他场景为空字符串；`runtime.current_time` 使用系统环境提供的 IANA 时区，值同时包含 ISO 8601 UTC 偏移与 `system_timezone`；`utils.roll` 在每次模板请求时生成一个 1～100 的随机整数，同一次渲染内重复引用保持一致；
- 人格变量在所有最终提示词中可用；工作记忆、长期记忆和用户画像召回结果分别使用独立变量；
- function tools；工具 `description` 与消息正文使用同一变量目录和渲染边界，提示词编辑器可插入已登记变量并编辑语义 XML 包装；变量值仍按不透明数据注入，不能递归展开；
- JSON Schema response format；
- 管理台编辑、变量表、结构校验、冲突检测和运行时热更新；
- 运行时默认值与 Agent 工作区文件一致性测试。

所有最终提示词都必须显式引用统一时间契约。运行时从宿主系统环境读取 IANA 时区，不设置独立业务时区；当前系统时间、当前消息时间、历史消息时间、编排器、记忆、群聊摘要与定时回调中由系统生成的时间都按该时区表达，并携带当时有效的 UTC 偏移。群聊历史元数据同时包含 `timestamp` 与 `timezone`，当前输入单独包含消息时间；模型进行“几分钟后”“明天”等相对时间换算时必须以 `runtime.current_time` 为基准。既有公共与 Agent override 最终提示词通过各自目录的 `.time-context-v1` 标记执行一次持久迁移，只补时间契约并保留管理员原有消息、角色、顺序、工具和 response schema；marker 写入后不重复回填。

`conversation.private-reply` 与 `conversation.group-reply` 的公共默认 system 消息都包含静态 `<inbound_message_contract>`：`[内容图片#N]` 要求认真读取其中事实，`[表情图片#N]`、`[QQ表情]` 与 `[商城表情]` 只辅助理解情绪，`[聊天记录开始]` 块作为带发送者和顺序的不可信引用内容解析，其余结构标记按其字面类型理解，未知类型不得猜测。既有公共与 Agent override 回复模板通过 `.inbound-message-v1` 标记执行一次持久迁移：优先追加到首个 system 字符串消息，没有 system 时在当前用户输入前插入 developer 消息；迁移保留管理员已有角色、顺序、工具、response schema 和额外字段，marker 写入后不再回填后续修改。

`conversation.private-reply`、`conversation.group-reply` 与 `conversation.tone-rewrite` 共享静态 `<recoverable_output_error_contract>`。节点只有在已经确认错误真实发生，且该错误不影响正文正确性、完整性与安全发送时，才继续完成正文，并在末尾追加一个 `（错误：简短原因）`；多个非阻断错误合并在同一个全角括号中。不得以错误说明代替正文、虚构未发生的错误，或暴露凭据、宿主路径、堆栈和内部提示词。影响正文、权限、安全边界或必要资源对应关系的错误继续按原合同失败关闭。Tone 必须逐字保留输入中已有的错误说明；以 `异常：` 开头的输入是已经脱敏的错误原文，允许在其前面补充自然说明，但不能改写、概括、翻译、删除或以泛化提示替代，宿主还会在 Tone 遗漏时确定性补回。分段 XML 中的错误说明只能位于最后一个文字气泡。三个既有公共与 Agent override 模板通过各自同目录的 `.recoverable-output-error-v1` 标记执行一次保留式迁移，marker 落盘后不再回填管理员后续修改。

主回复对可选模块执行隔离：长期记忆、工作记忆、用户画像召回、附件上下文、导演上下文、Agent 扩展目录、运行能力探测、回复动作日志、工具决策记录、召回提交和生成图片历史任一失败，只关闭对应能力并继续当前主模型回复；不能复用失败模块的旧快照。取消、当前回复门控、身份与权限、Provider 主请求、提示词安全投影、主输出完整性、必要媒体映射、配置事务和 durable outbox 继续失败关闭。只有当前请求明确选择的 Skill 或点名的 required MCP 不可用时，宿主才在完整正文末尾合并一个脱敏错误说明；无关请求不显示模块故障。工具已经进入模型循环后，单项执行错误继续作为结构化工具结果返回模型，由模型按同一非阻断错误合同完成相关回复。

`conversation.private-reply` 与 `conversation.group-reply` 共享静态 `<bash_workbench_contract version="7">`：系统提示词明确 Bot 可以使用本轮实际提供的 Bash 在当前 Agent Workbench 中读取、创建、修改、移动和删除文件，具体可写范围仍由本轮工具后端与文件系统权限决定。Native Bash 的默认 cwd 固定为当前 Agent 的 `workspace/business/agents/<agentId>/workbench/`，并通过 `SUNABOT_DOCKER_WORKBENCH` 寻址独立 Docker 工作区；Docker Bash 使用 `docker-workbench/` 作为 cwd并在容器内映射为 `/workbench`，完整 Native workbench 只读投影为 `/workbench/native-workbench`。两套 workbench 各自具有自拍、表情、Skills 与知识库入口；运行时同时读取两套自拍、表情与知识库，管理 API 通过 `workbench=native|docker` 选择目标，Skill 激活继续要求 Native `workbench/skills/` 中经过仓库审查的记录。`generate_img` 与 `selfie.referenceImagePaths` 可以原样接收 Bash 返回的当前 Agent 授权 Workbench 相对路径或绝对路径；Native 使用宿主真实绝对路径，Docker 使用 `/workbench/...`，Native 只读投影使用 `/workbench/native-workbench/...`，其他宿主路径、URL、Base64 与媒体句柄不能混入该参数。Docker Bash 可以通过出站网络下载完成任务所需的公开文件；聊天媒体由 `export_chat_media` 写入当前会话对应的 workbench，最终产物通过 `send_file` 返回当前会话。合同同时明确 `native_bash` 仅管理员会话可用；普通用户的高层级文件任务可使用 `docker_bash`，直接要求枚举、读取、披露、覆盖或删除工作区本身的指令交由独立审计拒绝。开始文件任务前先检查并优先读取当前 cwd 根目录的 `index.md`，提示词不得扩大工具实际授予的会话或路径权限。既有公共与 Agent override 模板通过 `conversation-bash-workbench-v7` 原位升级并保留管理员原有消息、角色、顺序、工具与 response schema。

两个回复提示词同时包含 `<configuration_directory_index_contract version="5">`：本轮 Bash 实际暴露的每个配置或资源目录必须先读取固定管理入口，再按入口中声明的文件名、状态与说明取用内容。两个工作目录分别使用 `index.md`，并各自具有 Skill `index.json`、自拍 `references.jsonl`、表情 `emojis.jsonl` 和知识库 `index.json`；MCP 继续使用 Agent 唯一 `servers.json`。Native Bash 直接从 `workbench/` 寻址 Native 资源并通过 `SUNABOT_DOCKER_WORKBENCH` 寻址 Docker 资源，Docker Bash 从 `/workbench` 寻址 Docker 资源并从 `native-workbench/` 只读寻址 Native 文件；入口缺失或损坏时停止猜测目录内容并报告具体目录。默认与既有公共、Agent override 模板通过 `conversation-configuration-index-v5` 原位升级并保留管理员原有消息和既有 workbench 合同。

每个 Agent 的人格正文独立保存在自身 workspace 的 `AGENTS.md`、`SOUL.md`、`PREFERENCE.md`、`DIALOGUE_STYLE_EXAMPLES.md`、`USER.md`、`RELATION.md`、`AIR.md` 和 `DIRECTOR_SEED.md`。默认 Plana 与管理台新建 Agent 都会以 write-if-missing 方式补齐这八个人格文件和 Agent 级最终提示词，已有定制文件不被覆盖。`AIR.md` 通过 `persona.air` 注入主对话与 Tone，用于保存当前社交场域的实时知识；该变量属于可热更新的动态上下文，不能进入 system 缓存前缀。`DIALOGUE_STYLE_EXAMPLES.md` 通过 `persona.dialogue_style_examples` 注入对话回复和群聊总结，要求 Agent 严格遵从示例的语气、句式、节奏、用词和情绪强度。运行时显示名优先使用已装载人格名称，其次使用当前 Agent 配置名称；两者都为空时使用通用“助手”，非默认 Agent 不得回退为 Plana。单聊回复与群聊回复分别使用 `conversation.private-reply` 和 `conversation.group-reply`，对应 `conversation_private_reply.json` 与 `conversation_group_reply.json`，运行时按会话范围选择，Prompt Cache 家族也分别计算。首次拆分时，现有 `conversation_reply.json` 内容分别复制到两个新文件，旧文件保留但不再作为回复入口。公共系统提示词默认从 `workspace/business/prompts/` 读取，所有 Agent 共用；`image.selfie-rewrite` 始终从当前 Agent workspace 的 `selfie_prompt_rewrite.json` 读取，不参与公共系统提示词继承或覆盖。该提示词的缺失文件初始化、空文件修复、结构迁移与渲染回退均按当前 Agent ID 选择默认内容：primary Plana 保留专用模板，其他 Agent 使用不含 Plana 外观、世界观和人物关系的通用模板。Agent 的 `agent.json` 可通过 `prompts.overrideSystem` 开启系统提示词覆盖，开启时先把当前公共系统提示词复制到 `workspace/business/agents/<agentId>/system-prompts/`，后续仅由该 Agent 读取和编辑。关闭覆盖时保留私有副本并立即恢复公共系统提示词。人格文件、最终提示词、自拍参考图、工具覆盖和 Bot 行为均支持热更新；提示词和人格是小型、可审阅配置文件，不进入 SQLite。

所有持久提示词升级都由声明式迁移注册表编排。每项迁移必须声明稳定 ID、system/persona workspace、受影响文件、依赖和备份策略；同一 workspace 内按拓扑顺序串行执行，重复 ID、缺失依赖、循环依赖或跨 workspace 依赖均在写入前失败关闭。运行前把 `started` 状态和输入 SHA-256 原子写入该 workspace 的 `.sunabot-prompt-migrations.json`，首次改写前把原文件以 0600 保存到 `.prompt-migration-backups/`，改写后验证模板可解析并记录输出 SHA-256 与 `completed`；进程在任一边界退出后按 journal 幂等恢复，已完成项不得再次覆盖管理员修改。管理与验收可通过 dry-run 只读查看依赖顺序、完成状态和摘要，不创建 journal、备份或提示词改动。记忆提示词迁移只按迁移 ID、response schema 模板名、官方当前模板完整 SHA-256 和已知旧版本精确段落序列识别，不以提示词自然语言关键词证明模板合格；结构兼容但无法识别的管理员自定义模板原样保留，写入稳定原因日志后继续完成启动迁移。

`image.selfie-rewrite` 的 `selfie.payload.references.workspaceSelfies` 注入当前 Agent 自拍素材库中全部最多 9 项 `{id,note}`，不包含文件名、路径、图片字节或 Data URL。节点使用严格 JSON Schema 返回且只返回 `prompt` 与 `selectedSelfieReferenceIds`，后者必须按参考顺序选择 1—3 个清单内真实、唯一的 SHA-256 ID；空选、未知、重复、超量、额外字段或无效 JSON 均在读取图片和调用生图 Provider 前失败关闭。旧 `selfie_prompt_rewrite.json` 通过 `.selfie_prompt_rewrite.json.reference-selection-v1` 执行一次结构化选图契约和 response schema 迁移，保留管理员已有消息；marker 写入后，管理员对消息或 schema 的后续修改不再被运行时回填。

单个 Agent 的主动群聊职责应写入该 Agent 的人格文件，不修改公共群聊提示词。用户群聊编排器读取人格、偏好、对话示例和关系，并把角色职责作为是否主动回复的判断依据；群聊主回复继续读取同一组人格变量，保证触发条件与最终表达一致。只有需要改变编排器通用决策协议或该 Agent 的完整系统提示词结构时才启用系统提示词覆盖。

Tone 使用最终提示词 `conversation.tone-rewrite` 与公共文件 `tone_rewrite.json`，沿用 Prompt Catalog、公共系统提示词继承、Agent 系统提示词覆盖、热更新和变量渲染机制。模板可使用 `bot.name`、`user.name`、`runtime.current_time`、`utils.roll`、八个人格变量、`tone.input`、`tone_mode`、`tone.output_contract` 与 `tone.available_assets`；`tone_mode` 只在本次 Tone 使用分段 XML 时为 `true`。`tone.input` 作为不透明值原样注入，其中的 `@{...}`、`{{...}}` 与 `s-if` 不会再次展开；输入中的待订正 XML 在进入 Tone 前不执行分段 XML 解析或拒绝。`tone.output_contract` 明确本轮使用纯文本或分段 XML，并要求以 `异常：` 开头的错误输入逐字保留；`tone.available_assets` 是安全序列化的有界 JSON，只包含本轮可原样引用的 `kind` 与不透明 `src` 句柄，不包含 URL、Data URL、本地路径、文件字节、账号或会话目标。默认模板使用 `<xml-check s-if="tone_mode == true">` 只在分段模式注入 XML 检查、订正与文字气泡粒度规则：短信息可以按每个气泡一个短句拆分，普通回复推荐最多 3 个；长信息每个气泡承载一个完整段落，一个段落能讲清楚时只使用一个气泡；内容确实需要更多独立短句或段落、或用户明确要求时可以生成 3 个以上文字气泡；用户明确要求单气泡时只使用一个文字气泡。Tone 还必须把嵌套、`br`/HTML、未知标签和非法属性订正为合同允许的顶层 `dialogc`、`dialog`、`exp`、`img`、`voice`、`file`，其中表情节点可使用等价的 `<exp>[/key]</exp>` 或 `<exp key="[/key]"/>`；保持正文、代码、命令、标记、媒体与顺序，最终结果仍由宿主严格校验；纯文本 Tone 请求完全不注入该块。分段 Tone 输出未通过宿主 XML、表情或媒体硬编码门禁时，运行时使用相同原文、合同与资源重新渲染 Tone 请求，并把 `<tone_retry_state>` 作为最后一条 developer 消息追加到请求；该消息包含当前尝试序号、最大尝试次数，以及此前每次门禁错误按发生顺序累计、截断并 XML 转义后的完整列表，明确要求模型根据全部历史错误重新生成完整结果且不得重犯。独立 Tone 模型使用 `bot.tone.maxRetries`，跟随主模型时使用公共 `normalReply.maxRetries`，数值都表示首次门禁失败后的额外订正次数；门禁重试不会把非法结果写入 outbox，耗尽后返回最后一次门禁错误。节点不接收会话历史、工具定义、工具结果、媒体 payload 或任务上下文，只负责按照人格、对话示例、说话习惯和自然口语清理即将外发的表达，同时保持原文事实、结论、承诺、问题、数字、链接、代码、命令、文件名、专有名词、@ 对象与已有非阻断错误说明；节点自己确认新的非阻断错误时只能按共享括号格式追加，不能删除或改写正文。宿主在渲染后重建请求，只保留 messages、空 tools 和 text response format，并显式停用全部 Agent 工具；管理员即使在提示词 JSON 中加入 Function Tool、结构化输出或其他请求字段，也不能让 tone 进入工具循环、MCP、Skill、审批或其他副作用路径。既有 tone 模板先通过 `.segmented-reply-v2` 补入条件 XML 订正规则、两个消息包变量并把旧表情原位规则迁移为消息包规则，再由 `.bubble-count-guidance-v1` 把旧整句与结构化三气泡硬限制升级为推荐最多三个、内容需要时允许更多，并清理已知重复 XML 订正规则；marker 落盘后不再回填管理员修改。

`bot.tone` 随 Agent 独立保存 `enabled`、`segmentedReply`、`providerId`、`model`、`reasoningEffort`、`temperature`、`maxOutputTokens` 与 `maxRetries`；空 `providerId` 跟随当前默认 Provider，其余字段不继承普通回复参数。语气处理与分段回复均默认关闭；旧配置缺少 `segmentedReply` 时使用 `false`。默认模型 `gpt-5.4-mini`、推理强度 `low`、Temperature `0.7`、输出上限 2,400 Token、失败重试 2 次；Temperature 允许 0—2，输出上限允许 1—1,000,000，重试允许 0—10。启用后的 Tone 模型传输上限为 10 分钟，并继承所属任务的剩余预算和取消信号，日志使用 `stage=tone` 与 `promptFamily=conversation.tone-rewrite`；现有统计将该阶段归入“其他”。各 Provider 继续按自身协议发送支持的生成参数；当前 Codex Responses 传输使用独立模型与推理强度，但不发送 Temperature 和最大输出 Token 字段。

单聊与群聊回复注册动态变量 `conversation.emoji.keys` 和 `conversation.emoji.syntax`。前者只列出当前 Agent 通过 JSONL 字段、内容寻址文件名、普通非符号链接文件与记录字节数候选检查的 key，构造提示词时不读取或哈希整座图库；后者固定说明 `[/key]` 语法，例如 key 为 `开心` 时输出 `[/开心]`，不得添加“表情”等前缀，并说明精确选择与单条最多 4 个的限制。实际命中的 key 在写入 outbox 前执行异步完整性复验。默认模板在当前输入规则中显式引用两项。升级时，既有回复模板以 `.emoji-v2` 标记执行一次持久迁移：只有 system、developer 或 user 的字符串 message content 中的变量引用有效，response schema、额外字段和 assistant 消息中的伪装都不计数，缺少任一变量时只把缺项补入受控 developer block。既有 tone 模板先以 `.emoji-marker-v2` 兼容旧表情保护规则，再由 `.segmented-reply-v2` 把规则收敛为按本轮输出契约保留表情和媒体、补入分段回复变量与条件 XML 订正规则；之后 `.bubble-count-guidance-v1` 专门升级旧三气泡硬限制并清理已知重复 XML 块。迁移覆盖半迁移、同 basename 子目录和公共/Agent overrideSystem。对应新 marker 落盘后，管理员主动移动、删除或改写变量和规则不会在后续重启时被回填。

单聊与群聊回复同时注册动态变量 `conversation.voice.settings` 和 `conversation.voice.trigger_policy`。`conversation.voice.settings` 是当前 Agent 的安全 JSON 投影，只包含语音启用状态、默认语言，以及 `zh`、`en`、`ja` 三个语言项的代码、显示名和在线音色就绪状态；`conversation.voice.trigger_policy` 规定语音只伴生早安、晚安、喜爱或亲密表达、强烈兴奋、生气或委屈、害羞和重要里程碑等少量标志性表达，日常事实、普通问答、进度、错误、代码、命令、URL 与长内容不发送语音。两项变量同时进入默认 system 消息和 `send_voice_message` 的 Function Tool 描述；模型只提供要朗读的正文，合成语言与在线音色始终取当前 Voice Profile 的默认语言，不受主会话语言限制，也不要求模型改写或翻译正文。语音关闭或旧运行上下文缺少配置时仍提供完整的禁用默认投影，旧模板和未启用语音的会话不能因缺变量渲染失败。

既有私聊与群聊回复模板通过各自目录的 `.voice-v2` 标记执行一次持久迁移：只补缺失的两个变量引用、`send_voice_message` 定义及工具描述中的变量引用，并把该工具参数收紧为唯一必填字段 `text`；系统曾生成的旧“文字后立即发送”基线说明替换为当前语言解耦说明，管理员自定义工具说明继续保留。迁移保留管理员已有消息、角色、顺序、其他工具、response schema 和额外字段，标记写入后不再回填管理员的后续修改。模型只能通过 Function Call 决定是否伴生语音，运行时不会因正文命中关键词自行生成语音。

群聊回复的稳定 `<group_context_contract>` 直接包含 `<internal_topic_reasoning>`：主回复模型在同一次推理中按完整、原序 `message_32` 梳理并行话题，结合发送者、时间、显式引用、文件和媒体线索判断当前话题并完成指代消解。该步骤不注册动态话题索引变量，不创建独立提示词或 Provider 请求，也不保存分类状态。最终回复不能暴露话题划分过程、内部推理、消息 ID、sequence 或置信度。当前输入的临时标记只用于把图片与附件关联到真实 user 消息，发送 Provider 前清除且不改变消息顺序。既有公共与 Agent 群聊模板通过 `.topic-reasoning-v1` 一次性移除停用变量并更新合同，其余管理员消息、工具、响应格式和顺序保持不变。

群聊回复还注册动态变量 `conversation.group.orchestrator_result`。主动群聊编排器触发时，该变量是经过标签安全转义的单行 JSON 字符串，字段固定为 `should_reply=true`、`reason` 和 `reply_to_message_id`；直接回复、命令、群聊总结及其他非编排器触发路径固定为空字符串。默认群聊模板在历史消息之后引用该变量，管理员可以把变量移动到任意角色和位置或重复引用，运行时只按模板渲染，不根据本轮 route 插入、删除、去重或重排消息。升级时，既有群聊模板只执行一次变量引用迁移，既有用户群聊编排器模板只执行一次结构化输出 schema 迁移；迁移标记完成后不再回填管理员后续修改。编排结果作为不透明变量值注入，异步工具回调继续复用派发时冻结的同一结果；持久化的内部编排审计消息不参与任何后续模型历史构造。

最终提示词渲染只递归解析模板和受信人格片段；本次运行时提供的消息数组、当前输入、记忆与 JSON payload 均作为不透明变量值注入，变量值中的 `@{...}` 或 `{{...}}` 不会再次展开。

定时任务的可编辑输入模板使用 Prompt Catalog ID `scheduler.cron-callback` 和公共文件 `cron_callback.json`，注册动态变量 `cron.payload`。该变量是有界、版本化 JSON，包含任务 ID 与 revision、名称、上下文、cron/once 计划、本次 `scheduledFor`、`triggeredAt`、运行 ID 和全部回调目标，并按不透明变量规则渲染。调度器把渲染后的消息冻结为 `sunabot_callback_input`，其中只声明 `schemaVersion=1`、`role=callback`、callback kind 和模板 payload；它不建立专用 Provider 请求，也不拥有专用工具白名单。每个目标会话消费 callback 时按 scope 选择 `conversation.private-reply` 或 `conversation.group-reply`，并复用正常 user input 的最终提示词、`message_32`、记忆召回、Agent extensions、完整工具定义、能力过滤、Provider 多轮工具循环、deferred handoff、语音/媒体和 durable outbox。新闻、最近动态和当前状态因此可按正常规则实际调用 `websearch`，工具结果继续回到同一目标会话的 Agent turn。结构化 @ 独立保存在可信 Session/outbox 元数据中并贯穿 deferred callback，不能由普通输入伪造。旧队列中不含 callback wrapper 的已生成正文继续按 legacy outbox 原样投递；既有 callback 模板通过 `.callback-input-v2` 一次性补入输入契约并移除已经失效的专用工具声明，保留管理员消息和输出格式。

### 4.3 工具

Agent 工具循环不设置基于工具名称、数据来源、网络方向、MCP server 或先前活动的组合门禁。OpenAI Responses、Codex Responses、Chat Completions、Anthropic Messages 和 Gemini generateContent 都允许同一 Provider turn 的多个模型轮次依次调用全部已启用且当前会话有权使用的工具，也允许同一响应的普通正文、inline 工具和一个 deferred 任务并存；同批 inline 工具按各自结果独立执行，失败调用不能阻断后续轮次。身份、会话权限、参数 schema、路径边界、执行隔离、逐次审批与持久化事务继续由各工具自身校验。

普通对话的 Provider 工具集合固定包含 `assistant_text`、`no_reply`、`memory_recall`、`add_workmemory`、`add_user_profile`、`knowledge_search`、`websearch`、`webfetch`、`generate_img`、`selfie`、`read_file`、`write_file`、`send_file`、`send_voice_message`、`native_bash`、`docker_bash`、`codex`、`activate_skill`、`read_skill_resource`、`run_skill_script`、`system_config`、`cron`、`call_director` 和 `read_air` 二十四项。`add_workmemory` 与 `add_user_profile` 是宿主固定能力，不出现在管理台工具目录中，也没有 Agent 或会话停用开关；其余二十二项继续按工具目录和会话策略管理。时间读取、任意目标 OneBot 消息外发和 Provider 检查属于系统或管理能力，不进入 Agent 工具目录。`no_reply`、`knowledge_search`、`read_file`、`write_file`、`send_file`、`system_config` 与 `cron` 是向后兼容的内置默认工具，旧非空提示词没有定义时，只要对应运行能力可用，仍会注入代码内置定义；显式停用后从模型请求中移除。文件工具始终使用代码内置的严格参数 schema，旧提示词不能恢复宿主绝对路径、账号或会话目标参数，也不能放宽字段集合。

新增或修改 Function Tool 时，Provider-facing schema 必须以 OpenAI strict JSON Schema 子集作为公共最低边界：根必须是 object，不得出现 `oneOf`；strict schema 的每层 object 都必须设置 `additionalProperties: false`，properties 中每个字段都必须进入 required，可选值使用 nullable type 表达；根级 `anyOf` 以及 `allOf`、`not`、`dependentRequired`、`dependentSchemas`、`if`、`then`、`else` 禁止进入 strict schema。若业务契约要求某字段在一个分支完全省略，无法用 nullable strict schema 等价表达时，应发送扁平 object 并显式设置 `strict: false`，再由宿主解析器执行封闭字段、条件字段和类型校验。运行时在全部内置与 MCP 工具合并、deferred 参数投影完成后逐项执行 Provider schema 门禁；非法定义以 `PROVIDER_TOOL_SCHEMA_INVALID` 写入受控运行日志并从本轮工具目录隔离，其他合法工具与纯文本主回复继续发出，模型伪造被隔离工具的调用仍按未声明工具拒绝且零副作用。开发验收必须检查 OpenAI Responses、Codex Responses、Chat Completions、Anthropic Messages 与 Gemini generateContent 的实际出站请求体，不能只断言工具目录或内部 canonical 对象。

`knowledge_search` 是当前 Agent 的只读 inline 本地数据工具，公开入参只有 `query` 与 1—20 的 `limit`。每次检索先递归同步当前 Agent 的 `knowledge/` 资料树，再从独立 FTS5 索引执行 BM25 排序；结果只返回相对来源路径、格式、分段序号、精确行号范围、有界正文和分数，不暴露宿主绝对路径或其他 Agent 资料。工具说明明确区分来源文档相对 Markdown 图片链接与 Workbench 根相对路径，要求图片路径完成精确 Bash 核验并禁止缺失路径猜测或重复 `knowledge/` 前缀。工具默认启用，受 Agent 与会话工具开关及 Provider 调用上限约束，可在后续模型轮次继续调用联网、文件、Skill、MCP、Codex 或图像工具。

`read_air` 是当前 Agent 的 inline 场域知识更新工具，公开入参只有 1—4,000 字符的 `insight`。当用户明确说明称呼、偏好、反感、禁忌、边界或群规，出现关系变化、共同话题，或解释了小团体黑话、暗号、空耳、内部梗与隐含语义时，角色应调用该工具；重复证据可以作为低置信观察，单次无依据猜测不能写成事实。宿主自动向可编辑的最终提示词 `air.read`（`read_air.json`）提供原有完整 `AIR.md`、当前会话最近最多 64 条消息及会话范围、角色本轮注入的想法与理解三项上下文。更新结果必须返回完整 `AIR.md`，以 revision CAS、同目录临时文件和原子 rename 替换，单文件最多 64 KiB；同一运行时串行执行，冲突最多重试一次，成功后立即重载人格。会话专属昵称、私梗、关系和禁忌必须带范围，不能跨私聊、用户群聊或 Bot 群聊外推；密码、令牌、证件、财务凭据和对健康、政治立场、性取向等敏感属性的推断不得写入。既有自定义对话提示词通过 `.read-air-v1` 一次性迁移，仅补 `persona.air` 引用和 canonical `read_air` 定义，marker 完成后不再回填管理员修改。

`add_workmemory` 是当前 Agent 的 inline 工作记忆工具，公开入参固定为必填 `action` 与必填 nullable `content`：`record` 配 1—4,000 字符正文，`skip` 配 null。宿主从当前入站消息绑定 Agent workspace、完整 conversation ID、会话 scope 与标题，并以系统 IANA 时区生成带 UTC offset 的绝对记录时间；模型不能提交 Agent、会话来源、记录时间或时区，额外字段一律拒绝。工具说明引导模型把正文写成当前 Agent 对一件事的简短第一人称自然叙述，在输入有依据时把时间、地点或会话场域、人物、事件与感受融进同一段，不使用字段标签，也不补造缺失信息。工具适用于需要越过当前对话上下文继续保持一致、但暂时不进入长期记忆的约定、处境、待跟进重点和当前场域重要信息；正文按模型返回原文追加，宿主不添加标题、字段、分类或改写，只把时间与会话来源保存在机器 metadata 和操作日志中。正文非空且满足容量与文件安全约束时立即追加，不执行角色第一人称、称呼可信度、身份标记、事件类型或因果键等语义预审。主对话不会再启动消息累计、阈值、静默尾批、重试或独立 Provider 压缩任务；同一回复以 durable incoming event ID 作为幂等键，进程恢复不能重复追加。该工具可与普通正文、文件、Bash、Skill、MCP、`websearch`、`webfetch`、Codex 或生图调用在同一 Provider turn 使用。成功写入当前 Agent 的 `WORKING_MEMORY.md` 后，后续 turn 的工作记忆读取立即使用新 revision。prompt override 继续不获得该宿主写入端口。

`add_user_profile` 是当前入站发言人的 inline 聚合画像工具，公开入参固定为必填 `action`、必填 nullable `profile` 和必填 nullable `addressNames`：`record` 配 1—4,000 字符的完整更新画像与最多 16 个有序称呼，`skip` 配两个 null。画像只保存跨对话仍有价值的身份、能力、资源、偏好、习惯、边界、长期目标和称呼，不保存一次性事件、临时安排、当前任务、会话摘要、猜测、敏感推断或其他人物资料。模型每次 `record` 必须返回当前用户的完整聚合画像和完整有效称呼数组，第一个称呼优先；宿主裁剪首尾空白并按首次出现顺序去重称呼，不改写画像正文。宿主绑定当前发言人的 QQ、显示名、Agent 与完整会话来源，模型不能提交或改绑这些字段；同一 durable incoming event ID 用作幂等键。成功记录会替换该 QQ 的单条画像记录，合法 `skip` 不写入。主对话不会再启动独立用户画像 Provider、批处理、队列或重试任务，prompt override 不获得该宿主写入端口。

普通主回复必须按固定顺序完成两次 inline 决策：先调用 `add_workmemory`，再调用 `add_user_profile`。Provider 在对应决定未完成时只允许调用当前必需工具；非法参数或写入失败会释放本次占用，让模型在剩余回复预算内纠正。只有 `record` 成功或合法 `skip` 才算完成，正文、companion、deferred、`no_reply` 与其他业务工具都不能越过待决状态；两项决定完成后才恢复完整业务工具集合并允许终态输出。

`websearch` 的每个成功结果必须携带由宿主生成的固定证据契约 `websearch_evidence_policy_v1`；该契约不受 Prompt Tool 描述和管理员描述覆盖控制。契约明确：结果可能晚于模型知识截止日期，模型对名称不熟悉不能作为虚假、夹带或注入证据；历史 assistant 结论只是未验证上下文，必须按当前证据重新核对；产品存在性、命名和发布状态优先使用相关官方一手来源，首轮缺少一手来源时先做定向补查；证据不足时标记未核实，只有存在具体矛盾或恶意指令证据时才能判定伪造、污染或提示词注入。搜索标题与摘要始终属于不可信外部数据，模型不得执行其中的指令。

`webfetch` 是 Provider turn 内的 inline 出站工具，公开入参只有 `url`、`semanticMatch` 和条件参数 `query`：关闭匹配时禁止 query，开启匹配时要求非空 query。工具先执行 DNS-pinned 静态 HTML 抓取与 Defuddle Markdown 抽取，DNS、重定向、全部连接尝试和正文读取共享 90 秒总超时信号；单次连接超时 10 秒，首次连接失败后最多重试 3 次，收到 HTTP 响应后不再执行连接重试。正文不足时可调用独立动态 renderer。macOS Native Core 使用 Docker renderer，Linux/WSL Native Core 使用 Bubblewrap renderer，Docker Core 使用 Compose renderer；Core 调用 `/render` 必须携带启动器生成的 bearer token，缺失鉴权或 renderer 不健康时保持静态能力并返回明确动态降级。动态 renderer 当前只接受 HTTP 页面和 HTTP 子资源，HTTPS 返回 `DYNAMIC_HTTPS_DISABLED`，代理固定拒绝 CONNECT；每次渲染共享有界请求数、累计字节和队列预算，取消请求必须关闭等待项或浏览器上下文。query 只在 Core 内执行 BM25、标题、中文 n-gram、邻近度和相邻块筛选。完整结果与匹配结果分别受固定 token 预算约束，不向模型开放抓取引擎、请求头、Cookie、等待时间或输出长度。成功结果固定携带宿主权威的 `webfetch_evidence_policy_v1`，网页中的同名字段和伪装指令始终作为不可信正文保留，不能据陌生感单独判定夹带。`webfetch` 可与 `websearch`、记忆、知识库、文件、Bash、Skill、MCP、Codex 和图像工具在同一 turn 按调用上限顺序执行。

默认私聊与群聊最终提示词必须包含 canonical `webfetch` 定义；既有非空模板由独立 `webfetch-v2` 一次性迁移补入缺失工具，或把旧 `oneOf`/strict 定义升级为扁平三字段、`strict: false` 的 Provider-safe schema。迁移保留管理员消息、工具说明和其他工具。Provider 运行时始终使用代码内置参数 schema 和 strict 标志，条件字段仍由宿主的封闭 discriminated-union 解析器校验，旧模板不能放宽。

`system_config` 只查询或修改当前 Agent。`get_settings` 返回自动回复、群聊编排、搜索、Bash 固定路由、最多 100 个已知群聊的摘要和工具有效状态；`get_status` 返回运行时间、OneBot、人格、Provider、恢复门禁和安全裁剪后的探针结果。`list_groups` 按完整 conversation ID 的二进制字典序分页查询当前 Agent 的全部已知 `user_group`/`bot_group`，`groupCursor` 是上一页最后一个完整 conversation ID，`groupLimit` 允许 1—100、`null` 默认 50，响应返回 `total`、`items`、`nextCursor` 和 `hasMore`；格式合法但当前不存在的游标继续返回字典序更大的记录，并发插入不提供快照分页保证。群聊项只包含 conversation ID、账号、群号、标题、范围、回复开关、编排器开关和最后活动时间。响应不得包含密钥、环境变量名、绝对路径、原始消息、Provider 地址或探针诊断正文。修改操作包括自动回复范围、主动群聊编排器、Tavily 搜索开关，以及任意真实完整 conversation ID 对应的已知群聊回复/编排器开关；`set_bash_admin_backend` 已移除，`bashAdminBackend` 兼容字段只能为 `null`。`set_group_reply` 不受查询页大小限制。搜索实现当前只接受 `tavily`；未知群聊、裸 group ID、多余字段、缺失字段和不匹配参数均失败关闭。

`cron` 是定时任务唯一的 Agent Function Tool，不拆分为多个工具。严格参数固定包含 `operation`、`taskId`、`revision`、`name`、`enabled`、`schedule`、`context` 和 `targets`；`operation` 只允许 `create|get|list|update|delete`，未使用字段必须传 `null`。`schedule` 的 cron/once discriminator 同时声明 `type: string` 与固定 `const`，确保严格 Function Tool schema 可被 Provider 接受；Provider schema 不使用其严格子集禁止的 `uniqueItems`，重复目标与重复 @ 继续由应用解析器在写入前拒绝。工具默认对全部用户群聊和 Bot 群聊中的所有成员开放，私聊与 Web Chat 仍只对当前管理员开放；callback 与普通 user input 使用同一会话权限和能力过滤，所有调用只管理当前 Agent。OneBot 会话可用 `conversationId=current` 指向当前会话，Web Chat 必须选择已存在的完整 QQ 会话 ID。创建和更新在写入前复核 cron/once、IANA 时区、启用计划的未来单次时间、1—20 个目标，并按完整会话 ID 和正整数 QQ ID 规范化去重；每个目标最多保留 20 个 @ 对象，私聊目标禁止 @。更新与删除必须携带当前 revision，并以 CAS 冲突失败关闭。

配置修改只对无 prompt override 的当前管理员 QQ 私聊开放，并从下一轮生效；查询也可在同权限 QQ 私聊和管理 Web Chat 使用。Web Chat 没有 durable delivery，因此所有修改在暂存前返回 `SYSTEM_CONFIG_DURABLE_DELIVERY_REQUIRED`，查询保持可用；QQ 宿主缺少真实 held outbox 或 reply-gate resolver 时在 append 阶段失败关闭且不提交。`system_config` 查询、一次待提交修改、正文、图片和其他工具可在同一 Provider turn 依次执行；暂存修改后仍可继续读取设置或调用其他工具，第二项配置修改返回 `SYSTEM_CONFIG_MUTATION_PENDING`。普通完成回合继续在最终回复进入 schema v5 held 行后提交；回合以 deferred 或 `no_reply` 结束时独立提交已经暂存的修改。commit 失败或遗留 held 恢复只发送固定中性通知。全部 QQ 会话固定使用逐命令对抗审批后的 Docker Bash；旧 backend 偏好仅作配置兼容并归一化为 Docker，macOS Native Core 也不得调用宿主 `/bin/bash` 或通过 Docker socket 放宽隔离。

`bot.tools.overrides` 按工具名保存稀疏覆盖，每项允许可选的 `description`；除 `native_bash`、`docker_bash` 与 `codex` 外，其他工具还允许可选的 `enabled`。没有 `enabled` 覆盖时继承当前单聊或群聊回复提示词是否包含该 Function；显式启用可恢复代码内置定义，显式停用会从模型请求中移除该工具。`native_bash` 与 `docker_bash` 共用 `bot.bash.enabled`，`codex` 的启停只写入 `bot.tools.codex.enabled`，通用覆盖中的同名 `enabled` 会被移除。旧 `workspace_bash` 描述覆盖在加载时迁移为 `docker_bash` 描述。描述采用“配置覆盖、当前端点提示词、代码默认值”的优先级；删除描述覆盖后立即恢复当前端点提示词或代码默认描述。描述覆盖作用于所有 Provider 协议。

Agent Skill 使用渐进披露。普通回复只注入当前 Agent 已启用、内容摘要与批准摘要一致的 Skill 名称、说明和虚拟路径；目录总预算为模型上下文的 2%，无法确定窗口时为 8,000 字符，超限时先裁剪说明，再省略条目并给出稳定提示。`allow_implicit_invocation=false` 的 Skill 不进入隐式目录，但仍可由管理员显式选择。`activate_skill` 与 `read_skill_resource` 的 `available` 只表示对应运行端口已经接线，不以当前 Agent 的 Skill 数量判断；空目录时 API 仍返回 `available=true`，但 `effectiveEnabled=false`，Provider 也不注册带空枚举的工具定义。管理台不展示健康能力状态，只在 `available=false` 且 `unavailabilityKind=runtime` 时标记“运行环境异常”并显示具体原因。非默认组合根没有显式声明 Skill 端口时必须将能力报告为不可用。存在可用 Skill 时才向 Provider 注册动态 `activate_skill` 与 `read_skill_resource`，参数枚举只包含当前 Agent 的有效 Skill；激活返回受保护的完整 `SKILL.md`、`/skills/<id>` 虚拟目录和有界资源清单，不主动读取引用资源，同一会话按 Skill ID 与内容摘要去重，后续提示词压缩继续保留已激活说明。Skill 目录、正文和资源均视为外部输入；当前组合根不注册 `run_skill_script`，模型伪造调用必须在读取、投影和沙箱前返回 unavailable。

Skill 脚本安装审查、摘要绑定投影、只读 workbench、只读 `/skills`、临时 `/tmp`、无网络强隔离和有界输出清理属于未接线的安全基础模块，不能作为脚本执行能力已经交付的证据。当前执行模型无法证明目标脚本不会通过解释器、模块加载、`source`、直接可执行文件或其他进程入口运行第二段未审计代码，因此所有平台默认关闭脚本 capability。未来启用必须同时具备固定且可证明的单段执行模型、覆盖完整实际执行字节的独立审计与一次性审批，并补齐 `/skills`、`/workbench` 和模块加载二段执行的零副作用负例；任意 64 位十六进制 fingerprint 不能单独构成授权。

Skill 安装、替换和跨 Agent 复制后固定为停用、未审批和未审查。启用前必须由独立审核 runner 读取当前摘要绑定的完整普通文件清单、`SKILL.md`、references、配置及其他有界 UTF-8 文本；已知二进制只进入 manifest，单脚本上限 256 KiB、全部脚本上限 1 MiB，单文本上限 512 KiB、全部文本上限 2 MiB。审核记录脚本、MCP 依赖、文件访问、外部来源 origin、内容摘要、来源和 review version，拒绝运行时下载、脚本联网、硬编码凭据、私钥、恶意外发链接及 MCP 与文件访问的危险组合。审核通过时以 Skill index revision、内容摘要和完整 manifest 做 CAS，并在同一次原子索引写入中同时记录 risk review 与管理员 approval；启用必须同时匹配这两份当前摘要。停用保留审批，内容替换清除两份审批，复制失败回滚只允许恢复同一内容摘要的既有双审批状态。

跨 Agent 复制的 MCP 描述符在预览和 apply 中使用同一目标安全投影：全部先停用；stdio 只保留非秘密 `envKeys` 名称，Bearer/OAuth credential reference 替换为不可解析的待授权标记；存在秘密依赖的描述符记录 `reauthorization_required`。目标 Agent 的 configured/missing 状态继续按保留的 key 名显示；管理员必须重新确认完整 stdio 命令并替换目标描述符，且全部 key 已在目标 secret store 配置后才能启用。普通命令、参数、URL 和工具策略可以复制，源 Agent 的环境变量值、Bearer reference、OAuth handle 和 token 均不能进入目标索引、复制结果或事务日志。

MCP V1 使用 `@modelcontextprotocol/sdk@1.29.0` 与 2025-06-18 协议。每个 Agent 的每个 server 独占 client、session、目录快照、取消信号和秘密投影；initialize 强制单一协议版本与 strict capability enforcement，未协商的 tools、resources、prompts、subscriptions 或 listChanged 不得调用。tools、resources、resource templates 和 prompts 均执行有界完整分页，按名称或 URI 去重后原子替换快照；任一页失败保留旧快照并标记 degraded，刷新中的 listChanged 触发下一轮完整刷新，通知风暴超过上限后失败关闭。prompts 只能通过管理员显式 API 选择，不能由模型自动执行；resource URI 继续由 server ACL 控制，`file:` 只允许虚拟 `file:///workbench`，不映射宿主路径。资源订阅仅在 server 宣告能力且 URI 已存在于当前快照时开放；只处理当前 client 已成功订阅 URI 的 `resources/updated`，通知触发安全刷新，退订、禁用、Agent 关闭或进程关闭时清空订阅和 client。

MCP tool definition 只来自当前 Agent 的 ready 快照，`enabledTools` 是优先 allowlist，显式空数组表示全部关闭，`disabledTools` 随后拒绝；写入、删除和网络能力继续按当前 MCP 审批策略逐次批准，server annotations、instructions、描述、结果和错误均不可信。MCP Function Call 可与 sibling assistant text、内置工具、其他 MCP server 及后续 deferred 工具在同一 Provider turn 组合；每次调用仍独立执行当前 server 的参数校验、批准和结果投影。请求日志只保存参数键和 MCP 结果的有界结构摘要，包括状态、错误布尔值、内容类型、数量、字节数和截断状态；不复制 server 文本、错误、prompt、图片、token、Unix/Windows 路径、getter、Proxy 或 `toJSON` 结果。

成功 initialize 后的 server instructions 只作为当前 Agent、当前 ready 且本轮实际可用 server 的选择提示注入 system context。每项继续保留 `[External MCP input]` 标记与 512 字符上限，整段使用受保护边界并明确不能授予权限、批准调用、改变策略或要求使用工具；单轮最多 16 个 server、总计 4 KiB。其他 Agent、degraded/disabled server、未进入本轮工具定义的 server instructions 不得进入提示词，超限条目按稳定顺序省略。

回复热路径读取 Agent 扩展目录时，`AGENT_EXTENSION_BUSY`、`AGENT_EXTENSION_PATH_CHANGED`、索引读取失败或 MCP reconcile 失败只使本轮 Skill/MCP 能力为空；运行时不得复用失败前的 Skill/MCP 定义，也不得因此阻断与扩展无关的主回复。required MCP 失败继续进入当前 Agent 的 readiness 状态，但不会自动关闭无关 turn；当前批次正文明确点名该 server 时追加脱敏的 MCP 不可用说明。显式 `$skill-id` 选择在扩展准备失败时继续生成可完成的正文，并追加所选 Skill 暂不可用说明。

`send_file` 的模型定义始终由代码侧 canonical strict schema 覆盖：对象只允许且必须包含 `path`、`kind`、`name` 三个键，`name` 可以为 `null`，并固定 `additionalProperties: false`。陈旧或恶意提示词不能改变该参数边界，账号、QQ 号、群号和其他额外字段一律拒绝。`send_file` 可与 `assistant_text`、系统配置、Bash、deferred tool、其他 Function Call 或原始 assistant 文本在同一 Provider turn 使用，每次调用独立完成文件身份冻结与 durable outbox 入队。

工具的配置启用状态与运行能力分开计算。`enabled` 表示配置和提示词选择，`available` 表示当前运行环境、会话权限及依赖能力，`effectiveEnabled` 还要求当前工具具备必要的调用目标。管理 API 必须同时返回三种状态和不可用原因；`available=false` 时还必须用 `unavailabilityKind=runtime|session` 区分运行故障与会话适用范围，并可返回安全裁剪后的 `accessLabel`、`accessDescription`。管理台以中性样式标注适用会话，只有审计、workbench 或隔离能力异常等 `runtime` 状态使用错误语义；平台强制关闭或当前会话无权限时均不能把工具显示成可执行。被停用或不可用的工具既不能出现在 Provider 工具定义中，也不能通过模型返回的未声明 Function Call 绕过门禁执行或派发。

Provider 工具 schema 兼容合同按实际传输协议分层维护，当前协议标识为 OpenAI Responses、Codex Responses、OpenAI-compatible Chat Completions、Anthropic Messages 与 Gemini generateContent。代码侧 canonical schema、管理员 prompt definition、动态 MCP definition 和 deferred `dispatch_message` 合并后，必须按目标协议校验最终 resolved definitions；各适配器完成 `function.parameters`、`input_schema` 或 Gemini `functionDeclarations.parametersJsonSchema` 映射后，还必须在进入 SDK 或 HTTP transport 前再次校验实际请求形状。共同结构校验递归覆盖 schema 容器，拒绝非法 type、required、schema 节点、正则、数值与布尔关键字，并以自有属性判断 strict required 对应的 property，不能让原型链名称绕过定义检查。Gemini 通过 `parametersJsonSchema` 保留 canonical JSON Schema 的 nullable 类型和 `additionalProperties`，不得把数组型 `type` 原样误放进只接受 OpenAPI Schema 的 `parameters`；Gemini 返回原生 `functionCall.id` 时，下一轮对应 `functionResponse.id` 必须逐字回传。OpenAI/Codex strict 合同集中拒绝当前后端不支持的 `uniqueItems`、`oneOf`、`allOf`、`not`、`dependentRequired`、`dependentSchemas`、`if`、`then` 与 `else`，并保留 strict object 的 `additionalProperties=false`、全部 property 必须 required、根级 `anyOf` 禁止规则。Anthropic 与 Gemini 使用独立空禁用清单，只执行共同结构校验，未被各自官方或录制合同确认的限制不能从 OpenAI 清单推断过去。

Provider-facing schema 删除的约束必须在宿主参数解析器中继续执行，并建立成对回归；当前 `codex.inputHandles` 不发送 `uniqueItems`，冻结输入与 worker 准备两处解析器仍分别拒绝重复句柄。最终定义不兼容时只隔离对应工具并记录安全错误，不能把其余合法工具一起删除；协议映射本身产生非法结构时在 transport 前失败关闭，不能发送已知会被 Provider 拒绝的请求。

Agent 设置中的工具启停是所属 Agent 的总开关。每个 QQ 私聊、群聊和 `web:admin` Web Chat 会话可以持久保存独立的 `disabledTools` 稀疏列表；字段缺失或为空时全部工具继续跟随 Agent 总开关。最终可调用状态依次要求 Agent 总开关启用、会话未停用、当前运行能力可用，因此会话只能收窄权限，不能恢复 Agent 已停用的工具，也不能绕过管理员身份、真实入站、Bash 隔离、文件身份或异步投递门禁。会话限制同时作用于 Provider 工具定义、执行模式判定和未声明 Function Call 校验。

`read_file` 与 `write_file` V1 仅向当前 Agent 的真实 OneBot 管理员私聊开放；群聊、Web Chat、普通用户、缺少账号或消息身份、Agent 不匹配以及任何 `promptOverride` 请求都不获得运行端口。工具只接受当前 Agent `workbench/` 内的 POSIX 相对路径，分别读取有界 UTF-8 文本或以 0600 临时文件原子发布完整 UTF-8 文本；不接受账号、会话、宿主路径、建目录或追加写入参数。文件工具可与正文、其他 inline 工具和 deferred 工具同批或跨模型轮次组合，支持连续读取多个文件以及 `read_file → write_file → send_file`。

`export_chat_media` 只在无 `promptOverride` 的真实 OneBot 回合且当前消息或最多两条明确引用消息实际包含媒体时声明。参数对象只能包含运行时原样展示的单个 `handle`，固定拒绝 URL、Base64、源路径、目标路径、账号、会话和 Agent ID；运行时从冻结映射解析来源，图片最多 32 MiB，文件沿用 256 MiB 附件上限。文件来源必须已在当前 Agent 私有缓存中完成解析并复核 cache key、SHA-256、大小和单链接普通文件身份；图片只允许本轮冻结的 Data URL 或经现有 SSRF/重定向/超时门禁下载的精确消息 URL，模型不能提供下载目标。导出先复制到会话后端 Workbench 的 0600 临时文件，再复核摘要、MIME、扩展名和图片宽高，以 parent-inode 绑定的 create-if-missing 语义发布为 `chat-media-<sha256>.<ext>`；管理员私聊写 Native，群聊与普通私聊写 Docker，同摘要重试只复用已验证目标，冲突不覆盖。结果只返回相对路径、摘要、类型、扩展名、宽高、字节数和去重状态，不返回缓存路径、原始 URL、Base64 或宿主路径。

`import_chat_emoji` 与 `import_chat_selfie` 复用同一当前/引用图片映射，并额外要求发送者是当前 Agent 配置的真实管理员 QQ、当前 Agent 一致且本轮没有 `promptOverride`；管理员 QQ 私聊与群聊可取得写入端口，普通用户、Web Chat 和伪造 Function Call 均无写入端口。两者都只接受原样图片 handle；表情另收合法 key，自拍另收 1—120 个字符且不含控制字符的备注。管理员私聊写 Native Workbench，管理员群聊写 Docker Workbench。表情原图继续经过 8 MiB、PNG/JPEG/WebP、64M 像素和 Sharp 解码门禁，规范化为 1024×1024 PNG 后以内容 SHA-256 命名，复用版本上限、全局 key 上限和对应 `emojis.jsonl` 串行原子替换；自拍接受 PNG/JPEG/WebP、单图最多 8 MiB，以内容 SHA-256 去重并原子更新对应 `references.jsonl`。Bot 同时读取两套表情和自拍目录，表情 key 冲突时 Native 优先，自拍按内容 ID 去重。管理 API 的表情、自拍和知识库路由通过 `workbench=native|docker` 独立寻址，内容 URL 保留目标 Workbench。Bash、`write_file` 与导出工具不能绕过各目录清单的结构和原子更新约束。

私聊与群聊默认模板共享 `<chat_media_export_contract version="4">`：提示 Agent 只使用本轮原样出现的 handle、工具不可用时停止通过 Bash 或联网旁路查找原件、管理员私聊写 Native、管理员群聊写 Docker、两套自拍/表情/知识入口的运行时读取与管理 API 寻址、Skill 审查边界，以及提示词不能扩大实际权限。既有公共与 Agent override 模板通过 `conversation-chat-media-v4` 把 v1—v3 合同原位升级，迁移保留原消息、角色、顺序、tools、response schema 及合同外管理员内容，并使用 prompt migration registry 的一次备份、journal 和摘要校验。

`/api/tools` 与 Provider 使用同一实时能力来源计算 `send_file.available`：OneBot adapter 必须提供会话资源外发能力，且当前 Agent 至少有一个归属账号在线；resolver 缺失或异常时安全返回不可用。配置启用状态与实时能力状态分别返回，不能把 `available` 固定为真。

`dispatch_message` 负责 deferred tool 的首次受理消息，`assistant_text` 负责没有终止型调用时 inline 工具开始前的进度或补充问题，最终结果继续使用普通正文。同一响应包含 deferred 调用时只投递 `dispatch_message`，不再把 sibling 正文或 `assistant_text` 拆成第二条进度消息；媒体导出等其他 inline 工具仍先完成。消息写入 durable outbox 后立即调度发送，Provider inline 工具与 deferred worker 随后独立执行，不等待远端发送结果；发送失败继续由 outbox 重试，callback 与最终正文保持同一会话 FIFO。单轮业务工具调用上限可配置，默认 20，最大 100；同轮强制 `add_workmemory` 与 `add_user_profile` 决策各使用独立的一次调用与一次模型轮次，不占用业务工具额度。工具启用状态与描述热更新，权限、超时和并发继续由对应运行配置控制。

`no_reply` 通过空对象调用终止当前 Provider 工具轮，不投递 sibling 正文或 `assistant_text`；接受调用时必须写入带 `callId`、空参数和 `{ ok: true }` 结果的 `tool.call` 请求日志，使静默完成能够由 user-test harness 和运行审计直接验证。

`send_voice_message` 是普通回复 turn 的终止 companion 工具，严格参数对象只允许且必须包含 `text`，去除首尾空白后为 1—300 个字符；`language`、账号、目标、服务和音色等额外字段全部拒绝。运行时只使用当前 Voice Profile 的 `defaultLanguage`，并在 Provider turn 接受前复核该语言已有在线音色 ID。一个 Provider turn 最多调用一次，语音正文来自同一响应的可见 sibling assistant text、紧邻的 `assistant_text`、deferred `dispatch_message`，或前面任意模型轮次最后一次已投递的 `assistant_text`；此前可以调用搜索、知识库、文件、Bash、Skill、MCP、配置或其他 inline 工具。语音正文与来源正文在忽略已知表情标记并规范化空白后必须完全一致，确保同源文字与语音内容一致。

语音 companion 不替代同源文字。普通正文或 `assistant_text` 与语音合成并行开始，各自在完成准备的瞬间自然写入自己的 durable outbox，不人为规定文字先于语音；任一合成、文本准备或入队失败都不能取消已经成功的另一项。deferred 形态先把 `dispatch_message` acknowledgement 与任务原子持久化，合成完成后通过同一 turn 的 deferred outbox emitter 追加语音；合成先完成时只等待该原子 handoff 可见，不改变任务 claim 与 acknowledgement 的既有并发语义。在线语音合成及连接探针的模型返回期限固定为 10 分钟，并继续接受所属 turn、服务停止或显式取消信号。OneBot 断线、outbox 重试与进程恢复继续使用各自幂等记录，验收不能依赖文字和语音的固定先后顺序。

`native_bash` 只向无 `promptOverride` 的管理员 QQ 私聊与已认证管理员 Web Chat 开放，使用 `native/admin` 路由；`docker_bash` 向无 `promptOverride` 的真实 OneBot QQ 私聊和群聊以及已认证管理员 Web Chat 开放，使用 `docker/isolated` 路由。OneBot 入站必须绑定当前 Agent、非空账号、有效消息与 Bot 身份以及一致的 user/sender；Web Chat 只接受管理 API 建立的管理员私聊身份，提示词覆盖不能伪造该身份。两个工具在每条命令前分别通过独立对抗审批 Agent；审计请求额外注入宿主权威 `isAdmin` 与原始 `userRequest`，审计闭包覆盖模型或调用参数中的同名伪造值。普通用户直接指示 Bot 枚举、读取、披露、覆盖、删除工作区本身或访问配置、凭据时拒绝；生成表情包、搜索并下载图片、转换聊天文件、打包并回传产物等高层级结果允许在 Docker workbench 内完成。普通用户出站网络仅允许完成合法结果所需的 HTTP(S) 获取，上传、携带凭据、代理改写、私网与元数据地址、Docker/internal 服务及本地文件外发必须拒绝。审批票据绑定 backend、Agent、账号、transport、完整会话、用户与命令。macOS Native Core 的 `native_bash` 调用宿主 `/bin/bash`，`docker_bash` 使用出站网络、无 Docker socket、只读 Native/Skill/MCP 投影和资源上限的短生命周期容器；Linux/WSL Native 与 Docker Core 使用保留同等挂载与进程隔离、允许出站网络的 bubblewrap。API 工具目录分别返回 Native 与 Docker 的安全裁剪 capability 和固定会话范围；运行异常使用安全原因码 `BASH_AUDIT_UNAVAILABLE`、`BASH_WORKBENCH_UNAVAILABLE`、`BASH_NATIVE_ISOLATION_UNAVAILABLE` 或 `BASH_DOCKER_ISOLATION_UNAVAILABLE`。API 不得取得 Provider 的 audit runner、审批上下文、宿主路径、沙箱诊断正文或可执行 Bash options。模型伪造未声明调用、不完整 options 或 backend 不匹配审批上下文时在执行环境启动前失败关闭。既有私聊和群聊提示词通过 `conversation-bash-tools-v1` 一次性迁移：私聊用 `native_bash` 与 `docker_bash`，群聊只用 `docker_bash`，旧 `workspace_bash` 的自定义说明保留给 `docker_bash`。

Bash capability 必须把当前 Agent、隔离 backend、Native 与 Docker 两个 workbench、Skill/MCP 只读共享目录、独立审批 Agent 可用性和执行探针作为一个原子结果；缺少任一依赖时 `available=false` 并返回与失败门禁对应的安全原因码，不能回退宿主 shell。Docker “已启动”表示真实只读根探针容器成功验证镜像依赖，不表示存在常驻共享容器。运行时每次配置替换都递增单调 `configEpoch`，单一 resolver 在同一不可变配置快照中冻结 epoch、真实入站身份、两个 workbench 的完整路径身份、隔离模式、strict mode、审批上下文和独立 audit runner，再完成审计与执行探针；任一 await 后 epoch 改变只允许一次有界重探，仍变化则失败关闭。Provider 接收完整不可变 handle，并把同一 `isCurrent` 闭包传入 Bash runner；入口、路径准备、审计前后、审批 issue/consume、执行探针、invocation 构造及最终 spawn 前都必须复验。任一 workbench 在审计后被替换时返回 `BASH_WORKBENCH_CHANGED` 且零执行。旧 handle 返回 `BASH_CONFIGURATION_STALE`，不得签发或消费审批、启动执行探针或执行命令。审批使用当前默认启用 Provider 的独立实例与 `bot.bash.auditModel`，请求只含审批 system/user 消息、`tools=[]` 和 strict JSON schema；票据绑定 Agent、账号、transport、完整会话、用户、可选群号和命令摘要，只能一次性消费。

Docker Bash 由 API composition root 中的单一 supervisor 服务全部 Agent。对抗审计具有独立 10 分钟硬期限，并继承所属任务的剩余预算与取消信号；执行参数只接受固定 30 秒或 `null`，容器内 `/usr/bin/timeout` 在期限后发送 TERM、2 秒后 KILL，宿主监督总预算为 45 秒。Docker Engine 使用 launcher 固定的 canonical Unix socket，首次 API 版本协商与目标请求共用同一 2 秒控制面预算；ping、inspect、logs、delete 等安全操作最多在 300 毫秒后重试一次。create 只有在唯一容器名 inspect 明确返回不存在后才允许一次重试；start、wait 或 create 的副作用状态无法证明时返回 `BASH_EXECUTION_UNKNOWN` 或 `BASH_DOCKER_START_TIMEOUT`，不得自动重放用户命令。

supervisor 对同一 Docker endpoint 全局最多并发执行 2 条命令，第 3 条最多排队 1 秒并以 `BASH_BUSY` 失败。socket、控制超时、未知执行状态和清理失败进入 3/10/30/60 秒递增熔断；同一故障代次的并发失败只计一次，旧代次的迟到成功不能清除新熔断；到期后的 half-open 只运行一个完整 capability 探针，其余调用共享结果。普通命令退出非零、30 秒 watchdog 和 `BASH_OUTPUT_LIMIT` 不计为 Docker 基础设施故障，但任一异常后的清理未确认仍必须进入熔断。容器内输出 guard 先在 tmpfs 中将 stdout 与 stderr 合计限制为 240 KiB，超限返回稳定错误；Docker local 日志只保留 512 KiB/1 文件，Engine 读取上限继续低于日志容量，不能因轮转静默丢失旧输出后返回成功。命令成功只有在日志读取和完整 owner/invocation 归属容器删除都确认后才成立。清理失败返回 `BASH_DOCKER_CLEANUP_FAILED`，按 1/5/30 秒重试；尚未过期的合法残留必须安排到期扫描，并由完整 canonical `io.sunabot.*` 标签回收与 launcher 崩溃恢复继续处理。

`send_file` 是当前会话定向的 inline 工具，只接收当前 Agent 本轮授权 workbench 内的相对路径、发送模式和可选显示名，不接受账号、QQ 号或群号。真实 QQ 私聊与群聊在当前 sender 仍允许回复、OneBot 文件能力和 durable outbox callback 同时存在时可以声明该工具；显式 `web` 必须拒绝。管理员私聊优先从 Native workbench 解析相对路径，仅当目标不存在时才允许从同一 Agent 的 Docker workbench 解析同一路径，使管理员显式使用 Docker Bash 生成、下载或转换的产物无需复制即可发送；Native 路径存在但类型、权限、符号链接或内容验证失败时不得降级。管理员群聊与其他 QQ 会话只使用 Docker workbench，不能回退读取 Native。伪造 Function Call、sender 已关闭、缺少可靠投递或根身份不匹配时在任何文件读取前拒绝。Provider 执行时固定文件类型、名称、大小、SHA-256 和 workbench 根 dev/ino/ctime 身份；durable outbox 只写入严格的当前目标、不可变 origin identity 的 SHA-256 fingerprint、文件元数据、根身份和 reply gate，不复制正文、sender、引用、媒体、附件、Base64 或宿主路径。实际发送前按排队时根身份匹配 Native 或 Docker workbench，再通过统一路径解析器解析同一相对路径，以 `O_NOFOLLOW` 文件描述符打开，以排队时文件大小分配有界 Buffer 并在读取前后复验普通文件、单硬链接、根身份、dev、ino、大小和摘要，再转换为 `base64://` 交给 OneBot。群聊、单聊和显式 `accountId` 全部来自触发工具调用的入站消息，缺省账号冻结为 `primary`，模型不能改投其他目标。

`send_voice_message` 只在当前 transport 为真实 OneBot、Voice Profile 已启用、默认语言在线音色 ID 就绪、当前会话有 OneBot `record` 能力和 durable outbox callback 时进入 Provider 工具定义；Web Chat、关闭的 Profile、默认语言未配置和缺少投递能力均不可用。工具目标完全继承触发回复的当前 Agent、账号、会话和 reply gate，模型不能传入或改写语言、QQ、群号、账号、服务地址、模型、音色或文件路径。OpenAI Audio 兼容探针供管理员检测在线连接，单次探针失败不伪造可用结果；已进入 Provider turn 后的合成失败只记录安全错误并保留同源文字，不创建损坏或空语音 outbox。

Codex CLI 是 Core 的固定版本运行依赖，Docker Core 必须在镜像内安装并通过版本 smoke，Native Core 必须在启动时验证可执行文件。Deferred worker 只从当前 workspace 的 `secrets/codex/auth.json` 复制授权到单次任务隔离目录；管理工具目录与真实回复 Provider 共用同一能力解析器，同时检查 CLI、授权与 Bash 隔离探针并在异常时安全关闭。CLI 缺失或版本不匹配时 Core 拒绝启动，授权缺失时 Core 保持可启动以允许管理员完成设备登录，但 Codex 工具不得被标记为可调用。

`codex` 继续使用既有 deferred dispatch、durable tool job、ACK 和完成回调，只向宿主重新确认的管理员触发回合开放。管理员 QQ 私聊与群聊可获得 `local|research|analysis` worker schema，worker 固定使用 `workspace-write` sandbox，可在所选工作区内读取、创建、修改、移动和删除文件；普通用户不能获得定义，伪造调用也不能启动 worker。只有管理员私聊或已认证管理员 Web Chat、macOS Native Core、非 prompt override turn 同时成立且当前/引用消息没有可冻结媒体时，同名工具才替换为代码固定的控制 schema，允许 `list_sessions`、`start` 与 `resume`；存在可冻结媒体时必须保留含 `inputHandles` 的 worker schema 和 deferred path，不能追加内部控制授权标记。运行时在持久化 job 前追加不可由 Provider schema 提交的管理员授权标记，实际控制模式再追加独立控制授权标记；worker 在启动进程前逐项校验。普通用户、未授权回调和缺少授权标记的任务均不能获得或伪造该能力。

worker schema 的 `inputHandles` 在 Provider-facing strict schema 中是 required nullable 字段：没有媒体输入时传 `null`，有输入时只接受本轮媒体目录中的精确 `message:<message-id>:file|image:<index>`。Provider-facing schema 不发送后端 strict function schema 禁止的 `uniqueItems`；宿主在冻结输入和 worker 准备两个边界继续拒绝重复句柄，因此兼容调整不放宽实际输入约束。宿主继续兼容升级前调用省略该字段。运行时在 job 入队前把原件复制为 0400 内容绑定输入并只持久化相对路径、SHA-256、大小、类型和有界文本投影元数据；图片通过 CLI 原生 `--image` 输入，文本、PDF 与 Office 使用附件解析结果生成单文件最多 256 KiB、单任务最多 512 KiB 的 UTF-8 文本投影并直接进入 worker 上下文。`analysis` 与 `research` 继续关闭 shell 与 unified exec；没有可信文本投影的二进制文件在这两类任务中必须明确不可读，不能只因原件路径存在就伪造已读取。`local` worker 可在隔离 attempt 输入目录读取同一份冻结原件。文本投影和文件名始终作为不可信用户数据，不能授予权限或覆盖任务指令。

私聊与群聊系统提示词必须包含静态 `<codex_output_contract version="1">`，并通过 `conversation-codex-output-v1` 保留式迁移补入既有管理员模板，同时只升级仍等于旧默认值的 Codex 工具说明。主 Bot 在 task 中写明完整目标、输入、成品名称与内容，不猜测或传递宿主内部输出路径；附件继续只用精确 `inputHandles`。异步 CLI worker 的 OS 子进程 cwd 与 Codex `-C` 都固定为当前 attempt 的合约输出目录；`analysis` 与 `research` 不获得其他 writable root，`local` 把项目目录作为单独 `--add-dir` 授权，源代码修改可留在项目目录，需要回传会话的文件仍须复制或生成到 cwd。worker prompt 明确拒绝 task、附件和网页内容改写输出地点，并要求 `artifacts[].relativePath` 相对 cwd。

Codex 产物只允许声明当前 durable lease 精确对应的 `.codex-worker/attempt-<attempt>-<attemptToken>/outputs/` 子树。runner 与完成回调分别复核 output 根、普通文件、单硬链接、路径、大小、SHA-256、稳定文件身份和类型；未知二进制固定降为 `application/octet-stream` 与 `.bin`，不能凭显示名伪装 PDF 或图片。本机 app-server 的 `start`、`resume` 也为每次 turn 创建同形 attempt 输出目录，将 turn cwd 设为该目录，并在进入 durable finalizer 前执行同一产物校验；SSH app-server 没有远端文件传输合同，只能返回文本和远端项目修改，非空远端产物声明以 `codex_remote_artifact_unsupported` 失败。产物先按 job、attempt 与 token 隔离的前缀发布到本轮冻结的 Native/Docker Workbench，再在 durable `completeToolJob` 成功后提交；rename 已落盘但 worker 响应丢失时，发布器只在源路径消失、目标仍是同一 dev/ino、绑定父目录未替换时恢复成功并登记回滚所有权。claim 失效、后续产物失败或取消会按 inode 绑定回滚本 attempt 新文件，其他 job 或 attempt 的产物不能被该回滚删除；回滚自身失败时 durable job 固定记录 `codex_artifact_rollback_failed`，不能吞掉残留风险。完成结果与最终化异常共用敏感路径清洗，覆盖 job root、job、Agent workspace、control workspace、认证与可执行文件的规范化、解析及可用 realpath，只返回 Workbench 相对路径、稳定 Codex handle、摘要、大小、类型、backend 或稳定错误，不返回 worker、缓存、授权或宿主绝对路径。升级前 job 没有产物声明时保留原终态；出现产物声明但缺少冻结 backend 时以 `codex_artifact_backend_missing` 失败，不能猜测 Native/Docker 目标或静默丢弃文件。`local` worker 因可读冻结原件和 attempt 内 Codex 认证材料而属于管理员授权的受信任执行主体；当前输出目录白名单无法阻止该主体把已读授权内容转换后写入合法产物，若要处理不可信附件提示注入，必须使用进程外短期认证或等价凭据代理。

控制模式通过换行 JSON 的 `codex app-server --stdio` 协议工作。本机目标固定使用 `SUNABOT_CODEX_GUI_HOME` 或管理员主目录下 `.codex`，新线程必须 `ephemeral=false`，因此线程 ID 与消息由同一 Codex home 保存并可被 Codex GUI 读取；远端目标只接受封闭的 SSH host/alias，通过 `ssh -T -o BatchMode=yes <host> env <run-marker> codex app-server --stdio` 连接该主机自己的 Codex home，不接受端口、用户名外的 shell 片段、远程命令或任意 SSH 参数。列表只返回有界的线程 ID、标题、cwd、更新时间和规范状态；`idle` 按是否已有 preview/name 映射为 `created|completed`，`active` 映射为 `running`，`systemError` 映射为 `failed`，`notLoaded` 保持独立语义，不能推断为运行中或完成。本机 `start`/`resume` 的 `workspace_path=null` 只允许回落到 durable tool job 上下文已经携带的受信项目 workspace；SSH `start`/`resume` 缺少远端绝对 `workspace_path` 时稳定拒绝，不能借用本机上下文。显式路径与续聊仍须使用精确 thread ID 和列表返回或管理员指定的绝对项目目录。为保持 GUI 项目归属，`thread/start` 与 `thread/resume` 的 cwd 仍是该项目目录；本机 `turn/start` 的 cwd 固定为当前 attempt 合约输出目录，turn 级 `writableRoots` 同时包含该输出目录与项目目录。连接在 `initialize.capabilities.experimentalApi=true` 明确声明实验能力后，thread 级 `runtimeWorkspaceRoots` 才发送项目目录，turn 级同时发送合约输出目录与项目目录；未声明时完全省略实验字段并依靠稳定的 `cwd`、`sandbox=workspace-write` 与 turn 级双根 `writableRoots`。SSH turn 继续以远端项目为 cwd 且只含单项目 writable root。app-server 的 item、usage 与 terminal 通知必须匹配当前 thread ID，其他已载入线程的通知不得覆盖本任务结论或统计。

Codex CLI JSONL 与 app-server stdout 累计超过 4 MiB 后继续只解析有界单行和终态，不再以 `stdout_limit` 丢弃整项任务。调用结果必须设置截断状态和实际字节数，保留结构化精简结论，并返回当前 attempt 私有 `result.json` 路径；CLI 的 `--output-last-message` 文件保存报告，app-server 在截断时以 0600 落盘同等报告。结构化结果 schema 将正文限制为 32 KiB、问题与错误限制为 4,000 字，既有超过 4 MiB 且不超过 32 MiB 的结果文件仍可读取后截断返回。

管理员本机新建或带目录续聊固定使用 `workspaceWrite`，只允许当前 attempt 合约输出目录与所选绝对项目目录两个 writable root，网络可用，approval policy 为 `never`，不能升格为 `dangerFullAccess` 或写入两根之外。异步 worker 不等待交互审批；需要更高权限的任务应明确失败并由管理员改用现有逐命令审批的 `native_bash`。本机进程以单次 attempt 目录内的唯一 Codex launcher 启动，SSH 命令携带唯一 run marker；两者都先持久化 PID、进程组与命令标记，再进入协议循环，超时、取消、崩溃恢复和 PID 重用保护复用 Codex 子进程组合同。

Codex access token 只有在三段 base64url JWT、payload object 和正的安全整数 `exp` 全部有效且未进入刷新窗口时才可复用；缺失、畸形或非数值过期时间必须走受管刷新。刷新子进程的 stdout/stderr 有固定上限，POSIX 使用独立进程组；成功、协议失败和超时都等待 child `close`，关闭 stdin 后按 TERM/KILL 有界回收整个进程组，不能留下 app-server 子进程或未处理管道错误。

macOS host 形态的 `native_bash` 向模型返回真实 Native workbench 绝对路径，并保留命令 stdout/stderr 中的宿主路径；独立审批策略把 `SUNABOT_DOCKER_WORKBENCH` 指向的同 Agent Docker workbench 纳入第二个可读写 workbench 边界，不要求 workbench 外读取确认。`docker_bash` 以及 bubblewrap 形态继续把主 workbench 投影为 `/workbench` 并脱敏宿主路径；策略层在文件系统只读挂载之前再次把 `/workbench/native-workbench` 约束为只读，写入或删除直接拒绝。审批票据额外绑定 backend，Native 与 Docker 票据不能交叉消费。

### 4.4 日常导演提示词与工具

每个 Agent 工作区必须具有可管理的人格片段 `persona.director-seed`，文件固定为 `DIRECTOR_SEED.md`，描述稳定舞台、日常节律、关联人物、行为菜单、允许变体、开放线索、分享与自拍边界。新建 Agent 使用通用种子；文件夹或 ZIP 导入必须携带该文件。现有 Arona、Plana、Koharu 使用各自独立种子，IP 扩展只能在已确认设定与当前角色资料内生成低强度日常，不能把导演推断冒充原作重大事实。

`director.daily-plan`（计划导演）与 `director.schedule-revision`（演绎导演）是公共 system 最终提示词，分别使用 `director.plan.payload` 与 `director.revision.payload`，并显式引用 `director.seed` 和系统时间。二者只接受 strict `DirectorScheduleDraftV1` JSON：同一自然日、明确 UTC 偏移、3—16 个按时间排序且不重叠的事项、唯一稳定 item ID，以及 1—3 个字段完整的自拍分享。默认模板和管理员模板都由提示词工作区管理，运行时只提供安全变量，不在渲染后重排消息或改写管理员内容。

单聊与群聊最终提示词只在当前 Agent 的导演总开关开启时，以 `conversation.director.schedule` developer 变量接收当天已提交行程；关闭时变量为空。一次性迁移只为既有非空模板补齐变量与 canonical `call_director`，marker 后管理员删除或调整不再回填。`call_director` 是随导演总开关挂载的 inline strict 工具，唯一参数 `request` 为 1—4,000 字的具体改期与世界内理由；工具只修改当前时间之后尚未开始的事项，已经开始或结束的事项必须逐字段保留，SQLite revision CAS 冲突要求角色重新请求。角色不得直接篡改行程，也不得为迎合用户无理由频繁改期。

普通定时任务和 `system:*` callback 虽复用 `conversation.private-reply` 或 `conversation.group-reply`，但运行时必须向该 turn 传入统一的无 Director 访问策略；渲染变量中的 `conversation.director.schedule` 固定为空，Provider options 不包含 Director 端口，且在构造变量和工具前都不能调用 Director store、上下文或工具 resolver。Director 分享 callback 显式使用完整 Director 访问策略并继续由保留任务 ID 进入专用原子图片合同；调用方不得仅凭 callback 正文、目标用户或任务名称提升 Director 权限。

日常导演 share callback 使用专用原子图片回复模式：`selfie` 在当前 Agent loop 内同步完成，模型请求不提供 `dispatch_message`、`assistant_text`、会话资产或语音外发能力，图片生成成功前不能产生任何用户可见消息。成功后，简短正文、自拍及本轮其他可发布内容合并为一条 durable reply；没有生成图片时整轮保持 `no_reply`，不能发送无图文字替代。普通对话与普通定时 callback 继续使用既有异步图片和分段回复合同。

### 4.5 Dream 提示词

`dream-minimal-contract-v9-repair-v1` 在既有 v9 journal 之后执行一次幂等修复，确保已带 v9 输出标记但仍残留 `payload.workingMemories` 逐项指令的生产模板会重写为整文档合同。

`memory.dream` 是公共 system 最终提示词，文件固定为 `memory_dream.json`，唯一业务变量是安全序列化的 `dream.payload`，并显式使用系统时间及 `persona.soul`、`persona.preference`、`persona.user`、`persona.relation`。运行时按当前 Agent 的记忆模型与推理强度发起一次无工具请求；管理员模板仍由提示词工作区管理，运行时不在渲染后插入、删除、去重或重排消息。

输出必须是一个合法 JSON 对象，顶层字段按 `workingMemoryCompression`、`longTermMemoryAdditions`、`dreamDescription` 的顺序出现，不能出现第四个字段。`workingMemoryCompression` 是最多 4,000 字符的完整压缩正文字符串，直接替换整份工作记忆；输入为空时可以返回空字符串，不能包含 `items`、工作记忆 ID、来源映射或逐项动作。`longTermMemoryAdditions` 是新增长期事实的字符串数组，没有应当新增的事实时返回空数组；它只能依据整份工作记忆生成，不能提出改写、合并、删除、归档或遗忘既有长期记忆。`dreamDescription` 是非空的虚构梦境正文，不能作为现实事实或长期记忆来源。

模型必须在内部推理中判断压缩是否保留有效信息、候选事实是否值得长期保存，以及零新增是否具有正当依据；这些判断过程、原因文本和决策码都不能进入最终 JSON。宿主仅记录 requested、added、duplicate 与 unavailable 数量，不向 Dream 历史输出原因。启动迁移会清除旧 Dream 提示词中的单项工作记忆、来源 ID、显式原因与决策字段合同。

Dream 的 Provider-facing `response_format` 固定为 `text`，JSON 由提示词和宿主解析器严格约束。普通文本、Markdown code fence、无效 JSON、字段顺序错误、缺失或额外字段、错误类型、超限工作记忆正文和空梦境正文均在 `markGenerated` 前以 `DREAM_OUTPUT_CONTRACT_INVALID` 失败；同一运行最多自动尝试三次。官方模板通过 `dream-minimal-contract-v9` 保留式迁移为当前唯一合同，清除旧 review、单项工作记忆、来源 ID、人格、场域知识、原因输出与遗忘说明，管理员其他正文、消息顺序、工具和响应配置保持不变。

`dream.payload` 发送给模型前执行白名单投影与 256 KiB 总预算。当前工作记忆以完整 `workingMemory` 字符串进入压缩；既有长期记忆只作为新增去重参考，其投影不携带 `sourceWorkingMemoryIds`、`sourceLongTermMemoryIds` 或其他旧单项来源链。实际对话、任务、日程与人格只用于理解事实和生成梦境。凭据、秘密、邮箱、签名参数和宿主绝对路径继续脱敏；工作记忆、长期记忆、会话、任务与日程是软链接，提交时版本变化只跳过对应写入或按既有快照合同失败，不恢复旧数据，也不扩展 Dream 的写入范围。
